# 単語帳（単語の詳細画面と、単語専用のデータ）— 設計書

- 作成日: 2026-10-07
- ステータス: ドラフト（Ownerの確認待ち。確認してほしい点は8章）
- 前提: `docs/design/2026-10-07-english-levels-design.md`（英語3,500語。問題の `meta.word`）、`docs/design/2026-10-06-question-explanation-design.md`（問題の解説）
- 参考にした画面: Ownerのご提示（モチたん風の単語詳細）、Google翻訳（意味を品詞ごとに並べる）

## 1. 目的

問題の中の1行（単語）だった英単語を、「単語」として調べ直せるようにする。
- 問題に答えたあと、その単語の意味・使われる場面・例文・似た単語を見られる。
- 単語帳（保存した単語）・苦手・覚えた、を自分で分けて、見返せる。

## 2. 今の状態と課題

- 単語専用のデータはない。単語は問題（`questions`）の一部で、`meta.word` に英単語、解説に要約1行があるだけ。
- 1語につき2問（英→日・日→英）あるので、「語」を単位にした記録（苦手・覚えた・単語帳）が持てない。
- 発音記号・例文・使われる場面・似た単語の内容は、まだない（Codexに作ってもらう。7章）。

## 3. 決定事項

| 項目 | 決定 |
|---|---|
| データ | 単語専用のテーブル `words`（語のマスター）と、`profile_words`（子どもごとの単語帳・苦手・覚えた）を新設する |
| 他言語 | `words.language` を持つ（英語 `en`。インドネシア語などを足すときも同じテーブルを使う）。今回は英語のみ |
| 音声（🔊） | 今回は作らない。画面に場所だけ空けておき、ボタンは出さない（別の作業。端末の読み上げ機能から始める方針） |
| 内容 | 発音記号・使われる場面・例文・似た単語は、内容ができるまで、**ある項目だけ**を画面に出す（空の見出しは出さない）。内容の作成は並行して進める |

## 4. データ設計

### 4-1. `words`（語のマスター）

| 列 | 型 | 中身 |
|---|---|---|
| id | bigint | |
| language | string(8) | `en` |
| word | string | 英単語（見出し語。そのままの大文字小文字） |
| key | string | 小文字の見出し語。`(language, key)` が一意 |
| level | unsigned small int | 英語レベル（1〜150）。語が最初に出るレベル |
| pos | string | 主な品詞（原稿の品詞） |
| cefr | string(2) null | A1〜C2（原稿にあるもの） |
| importance | tinyint | 重要度の★（1〜3）。既定はレベルから決める（レベル1〜60=★3、61〜100=★2、101〜=★1）。内容の原稿で上書きできる |
| ipa | string null | 発音記号（例: `ˈriːzn`） |
| meanings | json | 品詞ごとの意味 `[{"pos": "名詞", "ja": ["理由", "根拠"]}]`。原稿にない間は、`[{"pos": 原稿の品詞, "ja": [原稿の日本語]}]` |
| usage | text null | 使われる場面（子ども向けの短い文） |
| examples | json null | 例文 `[{"text": "Give me one good reason.", "translation": "納得のいく理由を1つ教えて。"}]`（最大3つ） |
| synonyms | json null | 似た単語 `[{"term": "cause", "note": "原因 / 引き金となるもの"}]`（最大5つ。品詞・使い方の違いも `note` に） |
| timestamps | | |

- 問題との結びつき: `questions.meta.word_id`（`english:import` が、語を書いたあとに付ける。いま `meta.word`〔小文字の語〕はあるので、それと `words.key` で結ぶ）。

### 4-2. `profile_words`（子どもごとの記録）

| 列 | 型 | 中身 |
|---|---|---|
| id | bigint | |
| user_profile_id | FK（削除で一緒に消える） | |
| word_id | FK（削除で一緒に消える） | |
| saved_at | timestamp null | 単語帳に保存した日時 |
| status | string null | `weak`（苦手）／`learned`（覚えた）／null |
| timestamps | | `(user_profile_id, word_id)` が一意 |

- 「苦手」と「覚えた」は同時にならない（どちらかを付けると、もう一方は外れる）。同じボタンをもう一度押すと外れる。
- 問題の覚え具合（`profile_question_memories`）とは別のもの。**手動のマーク**で、今回は出題の優先度には使わない（あとで「苦手を優先して出す」を足せる）。

### 4-3. 取り込み

- `english:import` が、単語のCSVから `words` も作る（語ごとに1行。同じ語を何度流しても増えない）。レベル・品詞・CEFR・日本語の意味・重要度の既定は、今の原稿から入る。
- 内容の原稿（発音記号・品詞別の意味・使われる場面・例文・似た語）は、別のCSV `word-details/*.csv` で受け取り、同じコマンドが読む（なくてもエラーにしない）。形は7章。
- `--fresh`（英語コースの入れ替え）は、`words` と、子どもの `profile_words` も消す。普通の再実行では、記録（`profile_words`）は消さない。

## 5. API

すべて `auth:sanctum` と、今のプロフィール（`ActiveProfile`）で動く。

| メソッド・パス | 中身 |
|---|---|
| `GET /api/words?filter=all\|saved\|weak\|learned&q=&page=` | 単語帳の一覧（1ページ50語）。語・品詞・主な意味・重要度・自分の状態を返す。下の「出す範囲」に従う |
| `GET /api/words/{id}` | 詳細（4-1の項目すべて＋自分の状態）。まだ出会っていない語は404 |
| `PUT /api/words/{id}/mark` | `{status?: "weak"\|"learned"\|null, saved?: boolean}` で、自分の状態を変える。連打しても同じ結果 |

**出す範囲**: 子どもが**出会った語**だけ。「出会った」は、その語の問題（どちらの向きでも）に1度でも答えたこと、または単語帳に保存したこと。未出会いの語を出さないのは、答えを先に見てしまわないため（と、3,500語が最初から並ぶと多すぎるため）。

## 6. 画面

### 6-1. 単語の詳細画面 `/words/[id]`

ご提示の画面のとおり、上から次の順に出す。内容のない項目は、見出しごと出さない。

1. ヘッダー: 戻る／重要度（★☆☆〜★★★）／単語帳へ（保存。保存済みは塗りつぶし）
2. 単語: 英単語（大きく）、発音記号。🔊のための場所は空けるが、ボタンは出さない
3. 意味: 品詞ごとに行を分ける（【名】理由、根拠、理性）
4. 使われる場面
5. 例文（英文と日本語訳）
6. 似た単語（語・説明。タップで、その語の詳細へ。出会っていない語は、タップできない）
7. 下の固定ボタン: ［✖ 苦手］［💡 覚えた！］［➡️ 次へ］。次へは、今見ている一覧（絞り込み後の並び）の次の語へ

日本語は、今あるふりがな（`AutoFurigana`）に通す。スマホ幅（375px）で、1画面に収まるように縦に並べる。

### 6-2. 単語帳 `/words`

- 上に絞り込みのタブ: すべて／単語帳／苦手／覚えた。検索（英語・日本語）。
- 一覧は、語・主な意味・重要度・状態のマーク。タップで詳細へ。
- 下のナビ（`BottomNav`）か「学ぶ」の画面から入る（入口は8章で確認）。

### 6-3. 問題の解説からのつながり

- 英語コースの問題で、答えたあとの解説（`answer-explanation`）に、「この単語を見る」のリンクを出す（`meta.word_id` があるとき）。
- 答えた時点で、その語は「出会った語」になる。

## 7. 内容の原稿（Codexへ依頼する形）

`words/details/*.csv`（原稿のフォルダ。複数ファイルに分けてよい。1語1行、合わせて3,500語。取り込みは `database/data/english/word-details/` から）。列（見出しの名前で読む。順番は自由）:

| 列 | 中身 |
|---|---|
| 英単語 | 見出し語（今の単語の原稿と同じ綴り） |
| 発音記号 | 例: `ˈriːzn`（記号の両側の `[ ]` は付けない） |
| 品詞別の意味 | 例: `名詞:理由,根拠,理性／動詞:論理的に考える` |
| 使われる場面 | 子どもに分かる短い文（1〜2文） |
| 例文1 / 例文1の訳 | 英文と日本語訳 |
| 例文2 / 例文2の訳 | 〃 |
| 似た語 | 例: `cause:原因|excuse:言い訳|logic:論理`（`語:説明` を `|` で区切る。説明は必須。最大5つ） |
| 重要度 | 1〜3（省略可。省略時はレベルから） |

- CSVは、「,」を含む列（品詞別の意味など）を `"…"` で囲む。例文は3つまで（列は `例文3`・`例文3の訳`）。空の列は、すでに入っている内容を消さない（上書きしたいときは書き直す）。
- 形式の誤りは、取り込みを止めず、ファイル名と行番号つきで報告する。
- 各レベルの子どもに読める言葉で書く（幼児・小学生低学年は、ひらがな中心・短く）。
- 私（Claude）が、列の形式・例文の文法・訳の自然さ・似た語が同じ原稿に存在するか・正しい発音記号の形、を検証してから取り込む（単語問題と同じ流れ）。

## 8. 確認してほしいこと

1. **単語帳に出す範囲**: 出会った語だけ（おすすめ）か、全語（先の語も見られる）か。
2. **入口**: 「学ぶ」の画面に「単語帳」のボタンを足す（おすすめ）か、下のナビに足すか。
3. **「苦手」「覚えた」の意味**: 今回は手動のマークだけで、出題には使わない。あとで「苦手を優先して出す」を足すか。
4. **重要度の既定**: レベルから決める（1〜60=★3、61〜100=★2、101〜=★1）。内容の原稿で、1語ずつ上書きできる。これでよいか。
5. **先に出す範囲**: 内容（例文など）ができる前に、画面とデータだけ先に出してよいか（空の項目は出さない）。

## 9. テスト

- サーバー: `words` の取り込み（件数・再実行で増えない・`meta.word_id`・意味の既定）、`word-details.csv` の取り込み（あるとき・ないとき・形式の誤りの報告）、API（出会った語だけ・絞り込み・検索・状態の変更が連打で同じ・別の子の記録が見えない・404）、`--fresh` で記録が消える。
- フロント（Vitest）: 意味の組み立て・次の語の選び方・内容のない項目を出さないこと。
- ブラウザ: スマホ幅（375px）で、詳細・一覧・解説からのつながり。確認後、検証用プロフィールを元に戻す。

## 10. やらないこと

- 音声（🔊）、苦手を出題に反映すること、語の画像・イラスト、インドネシア語など他言語の語（`language` 列だけ用意）、語の編集画面（管理画面）。

## 11. 実装の順序（実装計画で細かくする）

1. `words`・`profile_words` のテーブルとモデル。`english:import` が語を作る（`meta.word_id` も）。
2. `word-details.csv` の取り込み。
3. API（一覧・詳細・マーク）。
4. 詳細画面・単語帳の画面、解説からのリンク。
5. 確認（375px）、SPEC・TASKS の更新。
