## 1. 背景と目的

Ownerが実際に触って、次の点を指摘した。

1. ミニアプリの「クイズ」の欄は、約60のカテゴリーを全部並べていて、中身があるのは数件。動いていないものは出さない方がよい
2. スプルキャッチは、外から何のゲームか分からない。説明が要る
3. 簡単な問題では、答えが分かっていても、落ちてくるのを待たなくてはならず、ストレス。スプルが種を投げて、先に答えられるとよい
4. 英単語と国旗は、別のゲームとして作る

**うまくいった目安**

1. ミニアプリの引き出しに、動くものだけが並ぶ。カテゴリーが増えたら、画面を直さずに自動で出る
2. ゲームの名前と1行の説明が、引き出しで読める。遊ぶ前に、あそびかたが分かる
3. 落ちている言葉をタップすると、スプルが種を投げて、すぐ答えが決まり、次へ進める
4. 英単語と国旗のキャッチを、別々のゲームとして並べられる形になる（国旗は④で足す）

## 2. 決定事項（Owner確認済み）

| 項目 | 決定 |
|---|---|
| 引き出しの区切り | 「ミニゲーム」と「ミニクイズ」の2つ |
| ミニクイズに出すもの | **大もとのカテゴリーのうち、問題のあるステージが3つ以上ある**もの。3つは設定で変えられる。鍵の国のステージは数えない |
| 今のデータでの結果 | 「英語を学ぶ」だけが残る。「国旗」（ステージ1つ・中身は英語のあいさつ）と「世界遺産」（各国のカテゴリーの中にだけ問題がある）は、自動で隠れる。国旗クイズを作り込んでステージが3つ以上になれば、自動で出る |
| 説明 | 引き出しのゲームに、名前＋1行の説明。難しさを選ぶ画面に「あそびかた」の3つの手順。ゲーム中に「答えをタップ！」のヒント |
| 種を投げる | 落ちている言葉を**タップ**すると、スプルが種を投げて、その言葉で答えが決まる。どの高さでも投げられる。タップしなければ、今までどおり受け取る線で決まる |
| タップの意味の変更 | 今までの「列をタップ＝その列へ動く」を、**「タップ＝種を投げて答える」に変える**。スプルを動かすのは、◀▶ボタンと矢印キーだけ |
| 点数・コンボ・ハート・ごほうび | 変えない。サーバーは、終えたときに答えの並びを採点し直すだけなので、変更しない |
| 英単語と国旗 | いまのゲームの名前を「スプルキャッチ（えいたんご）」にし、ゲームの一覧に1行で入る形にする。国旗のキャッチは、④で別の1行として足す |

## 3. ミニクイズの一覧（サーバー）

### 3-1. 窓口

`GET /api/mini-quizzes`（ログイン済み）。大もとのカテゴリー（`parent_id` が空）を `order` の順に見て、条件を満たすものだけ返す。

```json
[ { "id": 63, "name": "英語を学ぶ", "stage_count": 54 } ]
```

### 3-2. 条件

- そのカテゴリー自身（`stages.category_id`）のステージのうち、**問題が1つ以上ある**ものを数える（子のカテゴリーのステージは数えない）
- **鍵の国のステージは数えない**（`Travel::lockedCountryIds`。ステージ一覧の窓口 `GET /api/categories/{id}/stages` と同じ決まり）。ログイン済みでプロフィールが選ばれていなければ、鍵の国は無いものとして数える
- 数が `config('quiz.mini_quiz.min_stages')`（初期値 3）以上のものを出す
- 計算は `app/Support/MiniQuizzes.php`（新規）に集め、窓口は呼ぶだけにする

## 4. スプルキャッチ（画面とゲームの動き）

### 4-1. 種を投げる（`catch-engine.ts`）

- 新しい関数 `throwAt(state, lane)`: 落ちている間（`phase === "falling"`）だけ働く。その列の言葉で答えを決め、○×を見せる段階（`feedback`）へ移る。点数・コンボ・ハート・答えの記録は、受け取る線で決まるときと**同じ決まり**（共通の関数 `settle` にまとめる）
- 言葉の高さ（`progress`）は、投げた瞬間のまま止める。スプルの列（`lane`）は動かさない（次の問題も同じ列から始まる）
- 状態に `lastVia: "line" | "throw" | null`（最後の答えの決まり方）を足す。見た目（スプルの絵・種の動き）にだけ使い、点数には関係しない
- 範囲外の列・落ちていない間・終わったあとは、何も起きない

### 4-2. 見た目（`catch-game.tsx`・`catch-view.ts`）

- 列の見えないボタンは、「その列へ動く」から「その列の言葉で答える（種を投げる）」に変える（`aria-label`: 「1列目の言葉で答える」）。◀▶ボタンと矢印キーは、今までどおりスプルを動かす
- 種を投げたとき、スプルの絵を種をまく動き（`sow-fly`）にして、小さな種が、スプルから言葉へ飛ぶ（0.28秒）。そのあと、今までの○×の見せ方（正解は喜ぶ・まちがいはがっかり）。種の動きは見た目だけで、出せなくても答えは決まる
- スプルの絵の決まりは、画面から離した関数 `spruPose(state)`（`back`・`throw`・`cheer`・`sad`）にして、テストする。投げたあとの最初の0.3秒だけ `throw`
- ゲーム中のヒント: 3・2・1の画面に「答えをタップ！」、◀▶ボタンの上に「◀▶でスプルを動かしても取れるよ」

### 4-3. 説明（`catch-select.tsx`・`catch-view.ts`）

- 難しさを選ぶ画面の見出しを「スプルキャッチ（えいたんご）」にし、その下に「あそびかた」の3つの手順:
  1. 問題が出るよ（上に出る）
  2. 答えの言葉をタップ！スプルが種を投げてキャッチするよ
  3. 10問やってみよう。ハートは3つ
- 文は `catch-view.ts` にまとめ（`CATCH_TITLE`・`CATCH_HOW_TO`）、テストで形を確かめる。子どもが読むので、`AutoFurigana` に通す

## 5. 引き出し（`learn/page.tsx`）

- 「ゲーム」の区切りを「ミニゲーム」にし、ゲームの一覧（`lib/mini-app.ts` の `MINI_GAMES`。名前・1行の説明・行き先）から、名前と説明つきのボタンを並べる。今は1つ（スプルキャッチ（えいたんご））。ゲームを増やすときは、一覧に1行足すだけ
- 「クイズ」の区切りを「ミニクイズ」にし、`GET /api/mini-quizzes` の結果を並べる（今までのカテゴリー全部の取得はやめる）。1つも無いときは「ミニクイズは、じゅんびちゅうだよ」と出す

## 6. テスト

- **サーバー（Pest）**: ミニクイズの一覧（3ステージ以上だけ・大もとだけ・問題のないステージを数えない・鍵の国のステージを数えない・順番・設定で数が変わる・ログイン必須）
- **画面（Vitest）**: `throwAt`（正解・まちがいで点数・コンボ・ハート・答えの記録が受け取りと同じ／高さを保つ／スプルの列を動かさない／落ちていないときと範囲外は何もしない／最後の問題で終わる）、`spruPose`、説明の文と手順、ゲームの一覧
- **ブラウザ**: 引き出しの表示、あそびかたの表示、タップで種が飛んで答えが決まる、◀▶で動かして受け取る遊び方も動く、3・2・1のヒント

## 7. やらないこと

- 国旗クイズ・国旗キャッチ（③④。別の設計）
- カテゴリーごとの「表示する」スイッチ（Owner管理画面。3ステージ以上の決まりで足りる間は作らない）
- 投げた速さによる点数（早く答えたら高得点、など）。今回は決まりを変えない
- ゲームの専用の説明ページ
