# 町の建物の大きさ（家2×2・大きな建物3×3／4×4）— 設計書

- 作成日: 2026-10-07
- ステータス: ドラフト（Ownerの確認待ち。確認してほしい点は8章）
- 前提: `docs/design/2026-09-27-spru-wave-e-design.md`（広がる地図・大きな建物）、`docs/design/2026-10-05-world-items-stage1-design.md`（建物の絵）。正式な建物の絵と大きさの決まりは、`company/spra/spra-world/assets/approved/building/`（`manifest.json` の `logicalFootprint`）

## 1. 目的

- Spruの家を2×2にして、町の中心として大きく見せる。
- モール・城・五重塔など、大きな建物を、その大きさ（3×3・4×4）で置けるようにする。小さい物を大量に置く町より、大きな建物でにぎやかにした町のほうが、立派に見えるようにする。
- 置ける物は「小（1×1）・中（2×2）・大（3×3・4×4）」の正方形にそろえる。長方形（4×3など）は扱わない（判定・描画・テストが広がるため）。

## 2. 今の状態

- 建物の大きさは、サーバー（`config/world.php` の `asset_footprints`）で、「1つの数字N（N×Nマス）」として決まる。今は2（2×2）のものだけ書いてあり、書いていない物は1×1。
- サーバーの置けるかの判定（`WorldPlacement`）と、画面の奥行き・置く範囲の計算（`footprintTiles`・`footprintCenter`・`depthTile`）は、**すでにNマスの正方形に対応している**。3や4にしても、計算は直さなくてよい。
- ただし次の3か所は、「2」を決め打ちにしている。
  - 絵の置き方（`item-art.tsx`）: 大きな建物は、いつも「2」として扱う（`isBigAsset(...) ? 2 : 1`）。
  - ショップの表示（`art-keys.ts`）: 大きな物に「・2×2」と書く。
  - 絵の大きさ: 絵は、**画像の横のピクセル数**で画面上の大きさが決まる（`image.width × UNIT_PER_PX`）。大きさ（マス）では変わらない。3×3・4×4にするには、その大きさに合わせた絵（横のピクセル数が多い絵）が必要。
- Spruの家は、地図の目印（`landmarks`）で、**1マス**（(1,1)）。前に畑（(1,2)）がある。

## 3. 決定事項

| 項目 | 決定 |
|---|---|
| 形 | 正方形だけ（1・2・3・4）。長方形は扱わない |
| Spruの家 | 2×2。絵は正式なもの（`approved/building/spru_house_01.png`） |
| 大きな建物 | 正式な建物の決まり（`manifest.json`）に合わせる: スプルモール・さくモール＝4×4、村長の家・風車と水車の庭＝3×3。ほかの正式な建物は2×2のまま。城・五重塔は3×3にする（Ownerの指定） |
| 長方形の建物 | 作らない |
| 置き物の個数の上限 | 今はなし。200個を超える子が出てきたら考える（Ownerの方針） |

## 4. 設計

### 4-1. 大きさの設定

- `config/world.php` の `asset_footprints` を、次のとおり更新する。

| 大きさ | 建物 |
|---|---|
| 4×4 | `spru_mall`・`saku_mall` |
| 3×3 | `chief_hall`・`windmill_garden`・`castle`・`pagoda` |
| 2×2 | 今のまま（ほかの建物・店・灯台・名所・大きな木など） |

- 画面（`art-keys.ts` の `isBigAsset`・ショップの「・2×2」の表示）は、サーバーが返す大きさ（`item.footprint`）を使う。「2」の決め打ちをやめる。

### 4-2. 絵

- 絵の画面上の大きさは、画像の横のピクセル数で決まる。大きさに合わせて、**大きな建物ほど、横のピクセル数を多くして書き出す**。目安は、2×2が約480px（今のまま）、3×3が約720px、4×4が約960px。
- 元の絵は、正式なもの（`approved/building/*.png`、1254×1254）。`tools/spru-assets/crops.json` に書き出す設定（`items`: キー・元の絵・範囲・横幅）を足し、`extract.py` で `frontend/public/spru/items/*.webp` に書き出す。
- 3×3・4×4にする建物の絵（`spru_mall`・`saku_mall`・`chief_hall`・`windmill_garden`）は、正式な絵から作り直す。城・五重塔は、今の絵（約500×440、約375×490）を3×3の位置に置くので、小さく見える。**城・五重塔の絵は、正式な建物の絵が届いてから作り直す**（それまでは、今の絵を拡大〔`ITEM_IMAGE_FIT.scale`〕で仮に置く）。
- Spruの家の絵は、`spru_house_01.png` から約480pxの2×2用を作る。夜の明かり（`IMAGE_LIGHTS.spru_house`）の位置は、新しい絵に合わせて直す。

### 4-3. Spruの家（2×2）と畑・道

- 家を、**地図の目印の「大きさ」を持てる形**にする（`landmarks` に `footprint`）。家は `(1,1)` を奥のマスにして、(1,1)・(2,1)・(1,2)・(2,2) の4マスを使う。置けないマス（`blocked`）も、この4マス。
- 畑を、**(0,2)** に動かす（家の左隣。下の道に面している）。道（(0,3)〜(6,3) の横の道、(3,1)・(3,2) の縦の道）は、そのまま。家の前（下）に道が来るので、動かさなくてよい。
- 家の画面の位置・タップの範囲・寝ているときの印（`SleepMark`）は、家の中心（2×2の真ん中）に合わせる。
- すでに (2,1)・(2,2) に置いてあるアイテムは、家に重なる（4-4で、バッグに戻す）。

### 4-4. 置いてある物の整理

大きさが変わると、すでに置いてある物が、広がった先の物・雲・地図の外・目印・道に重なることがある。

- 新しいコマンド `php artisan world:repair` を作る。置いてあるすべての物を、今の大きさで置けるか調べ（`WorldPlacement::check`）、置けない物を**バッグに戻す**（`x`・`y` を空にする）。戻した物は消えない。何度流しても同じ結果。戻した数を表示する。
- 本番・開発DBに入れるときに、このコマンドを流す（マイグレーションには入れない）。

## 5. テスト

- サーバー（Pest）: 大きさの設定（4×4・3×3の建物が、それぞれのマスを使う）、置けるかの判定（3×3・4×4が、地図の外・雲・目印・重なりで断られる。4×4が区画の中に収まる場所には置ける）、Spruの家の4マスが置けない・畑が(0,2)にある・道が動いていない、`world:repair`（置けない物だけバッグに戻る・置ける物は動かない・何度流しても同じ）、町のAPIが `footprint` を返す。
- フロント（Vitest）: 大きさの表示（2×2・3×3・4×4）、絵の置き方（大きさごとの位置）。
- ブラウザ: 375px で、家・モール・城を置いて見え方を確認（重なり・奥行き・タップ）。確認後、確認用のアカウントを消す。

## 6. 影響しないこと

- 区画の広がり方・解放レベル・敷地の上限は、今回は変えない（別の設計）。
- 置き物の個数の上限は設けない。
- 長方形の建物、アイテムの回転。

## 7. 実装の順序（実装計画で細かくする）

1. 大きさの設定と、画面の「2」の決め打ちをなくす。
2. 目印（家）に大きさを持たせ、2×2にする。畑を動かす。
3. `world:repair`。
4. 絵（家・モール・村長の家・風車の庭。城・五重塔は仮の拡大）。
5. 確認（375px）、SPEC・TASKS の更新。

## 8. 確認してほしいこと

1. **畑の位置:** (0,2)（家の左隣）でよいか。
2. **大きさの割り当て:** モール＝4×4、村長の家・風車の庭・城・五重塔＝3×3、ほかの建物＝2×2、でよいか（手順は4-1の表）。凱旋門・ビッグ・ベンなどの名所を3×3にしたいときは、お知らせください（設定を足すだけです）。
3. **城・五重塔の絵:** 正式な建物の絵が届くまでは、今の絵を拡大して仮に置いてよいか（小さな絵の拡大なので、少しぼやけます）。
