## 1. 背景と目的

限定公開で、知人・家族・親戚の子どもに遊んでもらう。感触が良いかを、**数字で**判断できるようにする。Owner管理画面に「分析」のページを作り、遊んだ人数・また来た割合・やめた場所・まちがいの多い問題・よく使われる遊び・遊んだ時間を見られるようにする。

**うまくいった目安**

1. 「分析」のページで、直近7〜90日の遊んだ人数・解いた問題数・正解率・遊んだ時間の推移が見られる
2. 登録した週ごとに、「その後どれだけ続いたか」が並んで見える
3. プレイヤーがどの段階でやめたかが分かる
4. まちがいの多い問題が、「へん」の報告数と並んで分かる
5. 見えている表を、CSVで書き出せる（Excelで文字化けしない）
6. 集計の表のおかげで、プレイヤーを消しても過去の数字が残る

## 2. 決定事項（Owner確認済み）

| 項目 | 決定 |
|---|---|
| 集め方 | 基本は、**いまあるデータで数える**。新しい記録は「遊んだ時間」だけ |
| 遊んだ時間 | **プレイヤーと1日ごとの合計秒数だけ**を記録する。どの画面を見たかは記録しない |
| 集計の表 | 日ごとの数字を表に保存する。今日の分は、そのつど数える |
| 定期の集計 | 毎日、日本時間の0時10分に、前の日の分を集計する |
| グループ比較 | **登録した週ごと**（プレイヤーを作った週）に分けて、週ごとの続き具合を並べる |
| CSV | 日ごと・登録した週ごと・まちがいの多い問題・User一覧を、書き出せる |
| グラフ | **グラフの部品（recharts）を入れる** |
| 外部の分析サービス | 使わない |

## 3. 数える物差し

- **遊んだ（答えた）**: 問題に1問でも答えた。記録は、答えの体力の行（`profile_currency_ledger` の `type = 'hp'`、`reason` が `answer_correct` か `answer_wrong`）。1回の答えには必ずこの行が1つある（復習の仕組みも同じ行を使っている）。解いた直後のやり直し（練習）は記録しないので、数えない
- **開いた**: その日に、遊んだ時間の記録（`profile_play_days`）が10秒以上あるプレイヤー。「答えずに町を見ただけの日」も入る（記録を始めた日から）
- **1日の区切り**: 日本時間の0時。データベースの時刻は世界標準時なので、`CONVERT_TZ(created_at, '+00:00', '+09:00')` で日本時間にして日付を取る
- **数える単位**: プレイヤー（子ども）。アカウントの数は、概要のカードの「登録アカウント数」などだけ
- **離れた人**: 最後に答えた日が7日以上前のプレイヤー（答えたことがなければ、プレイヤーを作ってから7日以上経った人）
- **登録した週**: プレイヤーを作った日（`user_profiles.created_at`）が入る、日本時間の月曜始まりの週

## 4. データとサーバー

### 4-1. 新しい表

**`profile_play_days`（遊んだ時間。1プレイヤー・1日で1行）**

| 列 | 型 | 内容 |
|---|---|---|
| `id` | 主キー | |
| `user_profile_id` | 外部キー | `cascadeOnDelete` |
| `played_on` | 日付 | 日本時間の日付 |
| `seconds` | 整数（0以上） | その日の合計秒数。初期値0 |
| `last_beat_at` | 日時 | 最後に受け取った時刻（秒数の水増しを防ぐための列） |
| `created_at` / `updated_at` | 日時 | |
| 一意制約 | | `user_profile_id` + `played_on` |

**`analytics_daily`（日ごとの集計。1日で1行）**

| 列 | 型 | 内容 |
|---|---|---|
| `date` | 日付（主キー） | 日本時間の日付 |
| `new_accounts` | 整数 | その日に登録したアカウント数 |
| `new_players` | 整数 | その日に作ったプレイヤー数 |
| `active_players` | 整数 | その日に答えたプレイヤー数 |
| `opened_players` | 整数 | その日に開いたプレイヤー数（10秒以上） |
| `answers` | 整数 | 解いた問題数 |
| `correct_answers` | 整数 | 正解の数 |
| `play_seconds` | 整数 | 遊んだ時間の合計（プレイヤー全員の秒数の和） |
| `created_at` / `updated_at` | 日時 | |

**索引（足すだけの移行）**: `profile_currency_ledger` に `(type, reason, created_at)` の索引を足す。

### 4-2. 集計の係（`app/Support/Analytics.php`、新規）

- `summary(): array`、`daily(Carbon $from, Carbon $to): array`（表の行を読み、無い日は、そのつど数えて補う。保存はしない）、`retention(): array`、`cohorts(int $weeks): array`、`funnel(Carbon $from): array`、`dropoff(Carbon $from): array`、`hardQuestions(int $limit): array`、`activities(Carbon $from, Carbon $to): array`、`aggregateDay(Carbon $date): array`（1日分を数えて返す）
- 数える処理（SQL）はここに集める。API は、期間を整えて呼ぶだけにする。回数を持たない遊び（復習・水やり）は、`count` を `null` にして返す。

### 4-3. 定期の集計（`php artisan analytics:aggregate`）

- `analytics:aggregate`（引数なし）: **前の日**（日本時間）を集計して、`analytics_daily` に保存（同じ日があれば更新）する。
- `analytics:aggregate --date=2026-10-05`: その日だけ。
- `analytics:aggregate --from=2026-10-01`: その日から昨日まで（取りこぼしの穴埋め）。`--from` に `earliest` を渡すと、データのいちばん古い日から。
- スケジュール: `routes/console.php` に、毎日 日本時間の0時10分に実行する、と書く。**本番では、サーバーの cron で `php artisan schedule:run` を毎分動かす必要がある**（本番の設計に書く）。開発では、手動で実行する。
- 集計に失敗しても、「分析」のページは壊れない（無い日は、そのつど数えて補う）。

### 4-4. API（Ownerだけ）

`GET /api/owner/analytics?days=14`（`days` は 7・14・30・90。それ以外は 14）

```json
{
  "days": 14,
  "summary": {
    "accounts": 12, "players": 20,
    "active_today": 4, "active_7d": 11, "active_30d": 15,
    "answers_today": 83, "play_minutes_today": 52
  },
  "daily": [
    { "date": "2026-10-03", "new_players": 2, "active_players": 4, "opened_players": 5,
      "answers": 83, "correct_answers": 61, "accuracy": 0.73, "play_minutes": 52 }
  ],
  "retention": { "d1": {"rate": 0.5, "base": 10}, "d3": {"rate": null, "base": 0}, "d7": {"rate": 0.3, "base": 7} },
  "cohorts": [
    { "week": "2026-09-28", "players": 8, "weeks": [1.0, 0.63, 0.5, null, null] }
  ],
  "funnel": [ { "key": "account", "label": "アカウント登録", "count": 12, "rate": null } ],
  "dropoff": [ { "key": "first_answer", "label": "最初の1問", "count": 3 } ],
  "hard_questions": [
    { "question_id": 41, "prompt": "…", "answers": 12, "accuracy": 0.25, "reports": 2 }
  ],
  "activities": [ { "key": "quiz", "label": "クイズ", "players": 9, "count": 214 } ],
  "feedback": { "new": 2, "read": 1, "done": 0 }
}
```

- 割合は 0〜1 の小数。**母数が0のときは `null`** にする（0で割らない）。画面は「まだデータがありません」と出す。
- `daily` は期間の全日を、古い順に並べる（無い日は0の行）。
- `cohorts` は、直近8週の「登録した週」ごと。`weeks` は、登録した週・1週後・2週後・3週後・4週後に、そのプレイヤーのうち遊んだ人の割合（まだ来ていない週は `null`）。
- `GET /api/owner/analytics/export/{daily|cohorts|hard-questions|users}`: CSV（`Content-Type: text/csv; charset=UTF-8`、先頭にBOMを付ける）。`daily` は `days` を受け取る。
- `GET /api/owner/users`: 今の項目に、`registered_on`・`players`・`last_played_on`・`answers`・`play_minutes` を足す（今までの項目は残す）。

### 4-5. 段階（どこでやめたか）の定義

期間内に作ったプレイヤーについて、次を**前の段階を全部満たした人の数**として数える（段階が順に絞り込まれ、割合が100%を超えない）。

1. アカウント登録（期間内に登録したアカウント）
2. プレイヤーを作る
3. 最初の1問に答える
4. 最初のステージをクリア（`profile_stage_progress.cleared_at`）
5. 3日以上遊ぶ（答えた日が3日以上）
6. レベル5になる
7. 最初の種をまく（`profile_seeds`）
8. 最初の旅に出る（`profile_trips`）

**離れた人の内訳**は、離れた人（3章）を、「満たした最後の段階」ごとに数える。

### 4-6. よく使われる遊び

期間内の、遊んだ人数と回数。ステージ・復習・スプルキャッチ・水やり・旅・おつかい・あいさつ。

| 遊び | 数え方 |
|---|---|
| クイズ（ステージ・復習の答え） | 答えの行（3章）。ステージと復習は、同じ画面で同じ答えの窓口を使い、答えの行には `stage_id` が付かない（付くのはステージクリアの行だけ）ため、**分けずに数える** |
| ステージクリア | `profile_stage_progress.cleared_at` が期間内（人数と回数） |
| 復習をやりきった | `user_profiles.last_review_on` が期間内のプレイヤー（人数のみ。回数は「—」と出す） |
| スプルキャッチ | `profile_game_plays`（`game = 'catch'`、`finished_at` あり）の `played_on`（人数と回数） |
| 水やり | `profile_seeds.last_watered_on` が期間内のプレイヤー（人数のみ。回数は「—」） |
| 旅 | `profile_trips.arrived_at` が期間内（人数と回数） |
| おつかい | `profile_errands.claimed_at` が期間内（人数と回数） |
| あいさつ | `profile_greetings.greeted_on` が期間内（人数と回数） |

## 5. 遊んだ時間の記録

### 5-1. 受け取り（サーバー）

- `POST /api/play-time`（ログイン済み＋プロフィール選択済み）。本文 `{ "seconds": 30 }`（1〜60の整数）。`throttle:6,1`。
- 今日（日本時間）の行を、なければ作る。増やす秒数は、**`min(seconds, 前回から経った秒数, 60)`** にする（`last_beat_at` との差。前回が無ければ `min(seconds, 30)`）。時計がずれたり、何回も連続で送られても、実際より多くは増えない。
- `last_beat_at` を今にして、`{ "seconds": 合計秒数 }` を返す。プロフィール未選択は 422。

### 5-2. 送り出し（画面）

- `frontend/src/components/app/play-time-tracker.tsx`（新規）を、ルートレイアウトに置く。プロフィールを選択中で、**画面が見えていて**（`document.visibilityState === "visible"`）、**直近60秒以内に操作があった**（タップ・キー・スクロール）ときだけ、30秒ごとに `{ seconds: 30 }` を送る。
- 送れなくても（通信エラー）、画面は止めず、何も言わない。
- Owner管理画面・ログイン前の画面では動かさない。

### 5-3. プライバシー

- 記録するのは、プレイヤーごと・1日ごとの合計秒数だけ。どの画面を見たか・何をしたかは記録しない。
- `docs/legal/` のプライバシーポリシーの下書きに、「遊んだ時間の合計を、1日ごとに記録する（サービスの改善のため）」を書き足す（追記）。

## 6. 画面

### 6-1. 「分析」のページ（`/owner/dashboard/analytics`、新規）

- メニュー「収益・運営」に「分析」を足す。上に期間の選択（7・14・30・90日。初期値14日）と、CSVの書き出しのボタン。
- **概要のカード**: 登録アカウント数・プレイヤー数・今日／7日／30日に遊んだ人数・今日解かれた問題数・今日遊んだ時間（分）
- **日ごとの推移**（recharts）: 遊んだ人数と開いた人数（折れ線）、解いた問題数（棒）、正解率、遊んだ時間（分）。表でも見られる
- **また来た割合**: 1日後・3日後・7日後（数字のカード。母数も小さく出す）
- **登録した週ごとの続き具合**: 行が「登録した週」、列が「登録した週・1週後・2週後・3週後・4週後」の表。割合が高いほど濃い色（色だけに頼らず、数字も出す）
- **どこでやめたか**: 段階ごとの人数と割合（横棒）と、離れた人の内訳
- **まちがいの多い問題**: 表（問題文・回答数・正解率・「へん」の報告数）
- **よく使われる遊び**: 表（遊び・人数・回数）
- **ご意見**: 状態ごとの件数と、「ご意見」へのリンク
- 色と見た目は、`dataviz` スキルの方針に沿って、既存のOwner画面（ライト・ダークの両方）にそろえる。数字は `lib/analytics.ts` の整形の関数（割合・分・日付・空の表示）を通す。

### 6-2. User一覧（`/owner/dashboard/users`）

- 登録日・プレイヤー数・最後に遊んだ日・解いた問題数・遊んだ時間（分）を並べる。メール確認の表示は残す。CSVの書き出しボタンを付ける。

### 6-3. CSV

- ボタンを押すと、`apiFetch` で取って、ブラウザの保存（`Blob`）で保存する。ファイル名は `spra-analytics-daily-2026-10-03.csv` のように、種類と日付を入れる。
- 先頭にBOM（`﻿`）を付けて、Excelで文字化けしないようにする。ダブルクォートと改行は、CSVの決まりでエスケープする。

## 7. テスト

### 7-1. サーバー（Pest）

- **物差し**: 日本時間の0時での区切り（14:59 UTCと15:00 UTC）、やり直し（練習）を数えない、1日の答えの数・正解率
- **遊んだ時間**: 受け取りの秒数の制限（前回からの経過を超えない・60秒まで）、1日1行、日をまたぐと別の行、未選択で422、回数の制限で429
- **日ごとの集計**: `analytics:aggregate` が前の日を保存し、2回目は更新する（行が増えない）、`--date`・`--from`、プレイヤーを消しても集計の表の過去の数字が残る、表に無い日（と今日）をそのつど数えて補う
- **また来た割合**: その日数が経っていない人を母数に入れない、母数0で `null`
- **登録した週ごと**: 週の区切り（日本時間の月曜始まり）、まだ来ていない週は `null`
- **段階と離れた人**: 前の段階を満たした人だけが次に進む、離れた人の最後の段階
- **まちがいの多い問題**: 5回未満は出さない、削除された問題、「へん」の報告数、正解率の低い順
- **よく使われる遊び**: 各遊びの人数と回数
- **API**: Ownerだけが見られる、`days` が不正なときは14、CSV（BOM・文字化けしない・エスケープ・Ownerだけ）、Userの一覧に項目が足されても今までの項目が残る

### 7-2. 画面（Vitest）

- `lib/analytics.ts`: 割合・分・日付の整形、空（`null`）の表示、CSVのエスケープとBOM、色の濃さの段階
- `play-time-tracker` の判断の関数（送るかどうか）: 見えている・操作の新しさ・プロフィールの有無

### 7-3. ブラウザでの確認

- 開発データで「分析」のページを開いて、崩れず出る／期間を切り替えられる／CSVが保存できる（保存した中身を確かめる）
- 遊んだ時間: 画面を開いてしばらく操作して、`profile_play_days` の秒数が増える／画面を隠している間は増えない
- 確認のあと、開発データベースを元に戻す（`profile_play_days`・`analytics_daily` の確認用の行を消す。町テスト id 7 の値は変えない）

## 8. やらないこと

- 画面ごとの閲覧の記録（遊んだ時間の記録は、合計秒数だけ）
- 招待コードごと・レベル帯ごと・難易度やカテゴリーごとのグループ比較（登録した週ごとだけ）
- リアルタイム表示
- アカウント単位の続き具合（プレイヤー単位だけ）
- 外部の分析サービス
- 本番のサーバーでの cron の設定（本番の設計で行う）
