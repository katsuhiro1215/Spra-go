## 1. 背景と目的

最初のリリースは**無料・招待制の試験公開**にする。登録できるのは招待コードを知っている人だけ。お金のやりとりは出さない。使ってくれた人の声（保護者の意見・問題のまちがい）を、Owner管理画面で読めるようにする。

**うまくいった目安**

1. 招待コードを知らない人は登録できず、知っている人は `/register?code=○○` のリンクだけで登録できる
2. 招待コードの変更・登録の一時停止・コイン購入の ON/OFF が、本番の更新作業なしにOwner管理画面でできる
3. 画面のどこにも「お金で買う」入口が出ない（遊んで貯めたコインとコインで買うアイテムは今のまま）
4. 保護者が文章でご意見を送れ、子どもは問題の画面でボタン1つで「へん」を報告できる。Owner管理画面で読み、状態を変えられる
5. スマホのホーム画面に置け、ネットが切れたときはスプルがやさしく知らせる

## 2. 決定事項（Owner確認済み）

| 項目 | 決定 |
|---|---|
| 招待の形 | **招待コードを1つ決めて、みんなに伝える**。コードは設定の1つで、漏れたら変える |
| コードの置き場 | **データベース**に保存し、Owner管理画面で見る・変える（`.env` には書かない） |
| コイン購入 | 公開設定の「コイン購入を使う」を **OFF** で始める。将来ONにするだけで戻せる |
| PWA | 「ホーム画面に追加」の案内＋つながらない時のやさしい画面（最小のサービスワーカー）。オフラインで遊べるようにはしない |
| ご意見 | **保護者向け**の文章フォーム＋子どもが押す問題の「へん」報告（自由な文章なし） |
| 分析 | この設計には入れない（次の作業） |

## 3. 公開設定と招待制の登録

### 3-1. 公開設定（データベース）

設定は3つ。1行ずつ「名前と値」で持つ（`app_settings` 表）。画面に出す前に型を整える係を `app/Support/AppSettings.php`（新規）に集める。

| 名前 | 型 | 初期値 | 意味 |
|---|---|---|---|
| `invite_code` | 文字（空あり） | 空 | 空なら招待コードは要らない（誰でも登録できる）。入っていれば登録に必須 |
| `registration_open` | 真偽 | 真 | 偽なら、コードを知っていても登録を受け付けない（一時停止） |
| `coin_purchase_enabled` | 真偽 | **偽** | 偽ならコインの購入ができない |

- 初期値の `invite_code` が空なのは、開発とテストで今までどおり登録できるようにするため。**本番を開く前に、必ずコードを入れる**（本番の手順に書く。さらにOwnerダッシュボードに「招待コードが空です（誰でも登録できます）」という警告を出す）。
- コードは前後の空白を取り、大文字小文字を区別せずに、`hash_equals` で比べる。

### 3-2. 登録（`RegisteredUserController::store`）

- `registration_open` が偽なら 403「いまは登録をおやすみしています」。
- `invite_code` が空でなければ、リクエストの `invite_code` を必須にして比べる。違えば 422「招待コードが違います」（`errors.invite_code`）。
- 登録の回数に制限を付ける（`throttle:10,1`）。コードを連続して試されないようにするため。
- ログインは変えない。すでに登録した人はそのまま入れる。

### 3-3. 登録画面が先に聞く窓口

- `GET /api/registration`（ログイン不要）→ `{ "open": true, "invite_required": true }`。コードそのものは返さない。
- `/register` はこれを読んで、コード欄を出す・出さない、「いまはおやすみ」の表示を切り替える。
- `/register?code=○○` で来たら、コード欄を埋めておく（LINEなどで送るリンク用）。

## 4. コイン購入を隠す

- `GET /api/coin-packages` は、`coin_purchase_enabled` が偽のとき `{ "enabled": false, "packages": [] }` を返す。ONのときは今の中身に `"enabled": true` を足す。
- `POST /api/coin-purchases/checkout` は、偽なら 403「コインの購入は、まだ始まっていません」。
- `frontend/src/app/shop/page.tsx` は、`enabled` が偽なら「コインを購入」の部分と購入後のメッセージを出さない。「コインで買う」アイテムのしくみは変えない。
- コインはゲームの中で貯めるもの、という今の遊びはそのまま。

## 5. ご意見

### 5-1. 表（`feedbacks`）

| 列 | 型 | 内容 |
|---|---|---|
| `id` | 主キー | |
| `user_id` | 外部キー | 送ったアカウント |
| `user_profile_id` | 外部キー（空あり） | 問題の報告のときだけ。どの子か |
| `kind` | 文字 | `bug`（不具合）・`request`（こうしてほしい）・`other`（その他）・`question_report`（問題の報告） |
| `body` | 文章（空あり） | 本文（2000字まで）。問題の報告では選んだ理由の名前を入れる |
| `question_id` | 外部キー（空あり） | 問題の報告のとき。問題が消えたら空にする（`nullOnDelete`） |
| `reason` | 文字（空あり） | 問題の報告の理由 `wrong_answer`・`unreadable`・`other` |
| `status` | 文字 | `new`（新着）・`read`（確認済み）・`done`（対応済み）。初期値 `new` |
| `page` | 文字（空あり） | 送ったときの画面のパス（200字まで） |
| `created_at` / `updated_at` | 日時 | |

- 同じ子・同じ問題の報告は1件にまとめる。`user_profile_id` と `question_id` を組にして、`kind = question_report` のときだけ重ねて保存しない（アプリ側で確かめ、再報告は成功扱いで何も増やさない）。

### 5-2. API

| メソッド・パス | 誰が | 内容 |
|---|---|---|
| `POST /api/feedback` | ログイン済みのアカウント | `kind`（`bug`・`request`・`other`）と `body`（必須・2000字まで）、`page`（任意）。`throttle:10,60`（1時間に10件） |
| `POST /api/questions/{question}/report` | ログイン済み＋プロフィール選択済み | `reason`（3つのどれか）。保存して `{ "reported": true }` を返す。`throttle:30,60` |
| `GET /api/owner/feedbacks` | Owner | 新しい順。`kind`・`status` で絞り込み。1ページ30件 |
| `PATCH /api/owner/feedbacks/{feedback}` | Owner | `status` を変える |

- Owner の一覧に出すのは「アカウント名」まで。メールアドレスは出さない（連絡が要るときは、Owner がユーザー画面で調べる）。

### 5-3. 画面

- **保護者のかたへ**: プロフィールを選ぶ画面（`/profiles`）の下に枠を足す。「ご意見・ご要望をおくる」を開くと、種類（3つ）と本文の欄が出る。送ると「ありがとうございます」と出す。
- **問題の「へん」**: 問題を出す画面（クイズ・復習・スプルキャッチ。どの部品に置くかは実装計画で確定）の端に、小さな「へん？」ボタンを置く。押すと3つの理由から選べ、選ぶと「おしえてくれてありがとう」と出す。
- **Owner管理画面**: メニューの「システム」の並びに「ご意見」を足す。一覧で種類・状態の絞り込み、状態の変更ができ、問題の報告の行からは、その問題の編集画面へ飛べる。

## 6. PWAの仕上げ

すでにあるもの: `app/manifest.ts`（名前・色・アイコン）、`public/icons/icon-192.png`・`icon-512.png`、`apple-icon.png`。足すもの:

### 6-1. 「ホーム画面に追加」の案内

- `/profiles` に案内の枠を出す。すでにホーム画面から開いている（`display-mode: standalone`、または iOS の `navigator.standalone`）ときは出さない。
- iPhone（Safari）: 「共有 → ホーム画面に追加」の手順を絵つきで見せる。
- Android（Chrome）: `beforeinstallprompt` を受け取れたら「ホーム画面に追加」ボタンを出し、押すと追加の確認を出す。受け取れないときは手順の文を出す。
- 「あとで」を押したら、その端末の `localStorage` に覚えて、出さなくする（読み書きは try/catch で囲む）。
- 端末の判定と出し分けは、部品から離した関数（`lib/pwa.ts` 新規）に集めて、テストできるようにする。

### 6-2. 最小のサービスワーカー

- `public/sw.js`。ページの移動（`mode === "navigate"`）の読み込みが**失敗したときだけ**、保存してある `/offline.html` を返す。それ以外の通信（API・画像・音）は一切さわらない。
- インストール時に `/offline.html`（スプルが「つながらないよ。ネットにつながったら、もういちど ひらいてね」と言う、自分で完結した静的な画面）だけを保存する。保存の名前に版を付け、更新時に古い保存を消す。
- 登録は本番のビルドのときだけ行う（開発中は動かさない）。`frontend/src/components/app/service-worker-register.tsx`（新規）をルートレイアウトに置く。
- オフラインでは遊べない（問題はサーバーから受け取る）。このことを案内の文には書かない。

## 7. Owner管理画面の「公開設定」

- メニューの「システム」の並びに「公開設定」を足す（`/owner/dashboard/settings`）。
- 招待コードの表示・変更（空にもできるが、空にすると警告を出す）、「登録を受け付ける」のスイッチ、「コイン購入を使う」のスイッチ。
- API: `GET /api/owner/settings`、`PUT /api/owner/settings`（Owner のみ）。
- ダッシュボードの要約に「招待コードが空です（誰でも登録できます）」の警告を足す。

## 8. テスト

### 8-1. サーバー（Pest）

- 公開設定: 初期値、変更、型（空文字は空とみなす）
- 登録: コード空なら今までどおり／コードありで正しい・違う・欠けている・前後の空白と大文字小文字の違い／`registration_open` が偽なら403／`GET /api/registration` がコードを返さない
- コイン購入: OFF で一覧が `enabled:false`・checkoutが403／ON で今までどおり（既存の `CoinPurchaseTest` は、ONにして通す）
- ご意見: 保存・文字数の上限・種類の不正・未ログインの拒否／問題の報告の保存と重複・不正な理由／Owner の一覧（絞り込み）と状態変更、他のロールの拒否
- Owner設定API: 保存、Owner以外の拒否

### 8-2. 画面（Vitest）

- `lib/pwa.ts`: 端末の判定（iPhone・Android・すでにホーム画面）と、案内を出す条件
- 登録画面のコード欄を決める関数（`?code=` の受け取り・欄の出し分け）

### 8-3. ブラウザでの確認

- コードあり／なしの登録、リンクでの登録、一時停止の表示
- ショップにコイン購入が出ない・設定でONにすると出る（確認後はOFFに戻す）
- ご意見の送信と、Owner一覧での表示・状態変更、問題の「へん」報告
- サービスワーカー: 本番ビルドで登録でき、ネットを切ってページを移動すると `offline.html` が出る
- 確認後に開発データベースを元の状態へ戻す（`app_settings` と `feedbacks` の確認用データも消す）
