## 1. 背景と目的

Owner は、ミニゲームを「ただの息抜き」ではなく、学んだことの復習につながるものにしたい。同じ問題のデータを、クイズとミニゲームの両方で使う。

ミニゲームは一度にたくさん作らず、まず2本作り、あとから足していく。

1. 1本目: **スプルキャッチ（英単語）**。この設計書で扱う
2. 2本目: **うちゅう旅行（宇宙）**。宇宙の問題づくりとあわせて、別の設計書で扱う

1本目では、2本目以降も使う共通の枠（問題の形・始める／終わるの API・遊んだ記録・結果の画面の形）を、必要な分だけ作る。

**うまくいった目安**

1. 「学ぶ」のミニアプリの引き出しから、スプルキャッチを始められる
2. 初級は、小さい子でも読んで動かせる速さと数（2択・約8秒）になっている
3. 最近まちがえた問題が先に出て、ゲームの答えが問題ごとの覚え具合に残る
4. 遊んでも HP は減らない。ごほうびは1日3回まで
5. 2本目を足すときに、遊んだ記録の表と始める／終わるの形をそのまま使える

## 3. 遊び方

### 3-1. 1回の流れ

1. 難しさを選ぶ
2. 「3・2・1」のあと、1問目が落ち始める
3. 10問を終えるか、ハートが3つなくなったら終わる
4. 結果の画面を出す

### 3-2. 1問の流れ

- 画面の上に問題文を出す（3-6）。選択肢が横一列に並び、上から一緒に落ちてくる。列の数は選択肢の数と同じ
- スプルは画面の下にいて、どこかの列に立っている。動かし方は3つ
  - 画面の下の「◀」「▶」のボタン（1列ずつ動く）
  - キーボードの ← →
  - 列を直接タップ（その列へ動く）
- 選択肢の列が、スプルの頭の高さ（受け取る線）まで来たら、スプルが立っている列の言葉を受け取ったことにする。どの列にも言葉があるので、かならずどれかを受け取る
- 受け取ったあと、少しのあいだ○×を見せて（正解 0.8秒・まちがい 1.6秒）、次の問題に移る。スプルは次の問題でも同じ列から始める。1問目は真ん中（列が偶数なら真ん中の左）から始める

| | 正解のとき | まちがいのとき |
|---|---|---|
| 点数 | +10点。コンボが3以上なら、さらに +5点 | なし |
| コンボ | +1 | 0に戻る |
| ハート | そのまま | 1つ減る |
| 見せ方 | 受け取った言葉がはずむ。スプルが喜ぶ（`actions/cheer.webp`）。正解の音 | 受け取った言葉がゆれる。正解の列を光らせる。スプルががっかりする（`expressions/sad.webp`）。まちがいの音 |

### 3-3. 難しさ

| | 初級 | 中級 | 上級 |
|---|---|---|---|
| 出す問題 | 「英語を学ぶ」の初級のステージの問題 | 中級のステージの問題 | 上級のステージの問題 |
| 列の数（選択肢の数） | 2 | 3 | 4 |
| 受け取る線まで落ちる時間 | 8秒 | 6秒 | 4.5秒 |
| 選択肢の長さの上限（`mb_strwidth`） | 16（全角8文字） | 14（全角7文字） | 12（全角6文字） |
| ごほうび（正解1問あたり） | 経験値3・学習ポイント3 | 経験値4・学習ポイント3 | 経験値5・学習ポイント3 |

- 数字はすべて `config/games.php`（6-1）にまとめ、遊んでみて調整する
- 選択肢の長さの上限は、列が少なく幅が広いほど長くする
- 問題の文そのものの長さは制限しない（上の問題文の欄で折り返す）

### 3-4. スプルの成長

1回のゲームの中で、画面のすみの印が育つ。その回の「いちばん長いコンボ」で決め、まちがえても戻らない。

| いちばん長いコンボ | 印 | 絵 |
|---|---|---|
| 0〜2 | 種 | `garden/seed.webp` |
| 3〜5 | 芽 | `garden/sprout.webp` |
| 6〜9 | つぼみ | `bloom/bud.webp` |
| 10（全問正解） | 花 | `bloom/flower.webp` |

対話では「コンボ10・15・20」と話したが、1回が10問なので届かない。3・6・10 に直した。

### 3-5. 点数

- 正解1問で10点。コンボが3以上になった正解は、さらに5点
- 全問正解で 10×10 + 5×8 = 140点
- 点数は、画面とサーバー（6-2）の両方で同じ決まりで計算する。記録に残すのはサーバーで計算し直した値

### 3-6. 問題文の見せ方

- 問題文が「」で始まるとき（例:「Hello」の意味は？）は、「」の中を大きく、残り（の意味は？）を小さく出す
- 文法の問題（例:「The man ___ is standing over there is my uncle.」空欄に入る最も適切な関係代名詞は？）も同じ分け方にする。「」の中が長いときは文字を小さくして折り返す
- 「」で始まらない問題文は、そのまま出す
- 漢字にはふりがなを付ける（`AutoFurigana`。クイズと同じ）。落ちてくる言葉も同じ

## 4. 出す問題

### 4-1. 使える問題

次のすべてに当てはまる問題を使う。

1. カテゴリー「英語を学ぶ」（`config('games.catch.category')` の名前で探す）のステージに入っている
2. そのステージの難しさが、選んだ難しさと同じ
3. そのステージの国に鍵がかかっていない（`Travel::lockedCountryIds`。今はアメリカ・イギリス）
4. 4択の問題（`multiple_choice`）で、正解が1つあり、まちがいの選択肢が「列の数−1」以上ある
5. 選択肢の言葉が、すべて3-3の長さの上限に収まる

開発用のデータで数えた、使える問題の数は次のとおり。1つの問題が2つのステージに入っていることはない。

| | アメリカ | イギリス | 両方 |
|---|---|---|---|
| 初級 | 43 | 47 | 90 |
| 中級 | 39 | 35 | 74 |
| 上級 | 19 | 23 | 42 |

アメリカにだけ着いたときは、上級で19問になる。1回10問は出せるが、同じ問題が出やすい。

### 4-2. 出す順

1回で10問（`question_count`）を次の順で選ぶ。

1. **最近まちがえた問題**: 覚え具合の「最後の答えがまちがい」（4-4の `wrong_on`）が付いている問題。まちがえた日の新しい順
2. **復習の日が来た問題**: 今の覚え具合の出す日が今日までの問題（覚えた問題は除く）。出す日の古い順
3. **残り**: 使える問題のうち、1にも2にも当てはまらない問題からランダムに選ぶ。それでも足りないときだけ、1・2で入りきらなかった問題を、1・2の順で足す

1と2はあわせて6問まで（`review_max`）にする。まちがえた問題ばかりにすると、子どもがくじけやすいため。

- 選んだ10問は、出す順をまぜる
- 使える問題が10問より少ないときは、ある分だけ出す。0問なら始められない（6-3）

### 4-3. 選択肢

- 正解と、まちがいの選択肢からランダムに「列の数−1」個を選び、まぜて列の順にする
- サーバーで選ぶ。画面はそのまま左から列に並べる

### 4-4. 覚え具合への記録

- ゲームの答えも、クイズと同じく `QuestionMemory::record` で問題ごとの覚え具合に書く
  - 復習の日より前に正解しても段階は上がらない。まちがえると段階1に戻る。ゲームで遊んでも、復習の予定はくずれない
- 「最近まちがえた」を見分けるため、表 `profile_question_memories` に `wrong_on`（日付、空でもよい）を足す
  - まちがえたら `wrong_on` にその日を入れる。正解したら空に戻す
  - クイズの答え・毎日の復習・ゲームのどれでも同じように動く（`record` の中で書くため）
  - 今までの記録には入れない（これからの答えから付く）
- 途中でやめたとき（3-7）は、何も記録しない

### 4-5. 正解を画面に渡すこと

ゲームの中ですぐに○×を出すため、始めるときの返事に、問題ごとの正解の選択肢の番号を入れる。クイズ（答えるたびにサーバーで判定し、正解を渡さない）とは違う。

- 終わったときに、サーバーで答えを採点し直す。記録・ごほうび・自己ベストは、サーバーで採点した値だけを使う
- 開発者ツールで正解を見る抜け道は残る。ごほうびは1日3回までで、コインも出さないので、影響は小さい

## 5. 記録とごほうび

### 5-1. 表 `profile_game_plays`（新規）

ミニゲームを1回遊ぶごとに1行。2本目以降のゲームも、この表を使う。

| 列 | 型 | 中身 |
|---|---|---|
| `id` | | |
| `user_profile_id` | 外部キー（プロフィールを消したら一緒に消す） | 遊んだプロフィール |
| `game` | 文字列 | ゲームの名前（`catch`） |
| `difficulty` | 文字列 | 初級・中級・上級 |
| `question_ids` | JSON | 出した問題の番号（出した順） |
| `finished_at` | 日時（空でもよい） | 終えた日時。空なら途中 |
| `played_on` | 日付（空でもよい） | 終えた日（`Garden::today()`）。1日の回数を数える |
| `answered_count` | 整数（空でもよい） | 答えた数 |
| `correct_count` | 整数（空でもよい） | 正解の数 |
| `score` | 整数（空でもよい） | 点数 |
| `best_combo` | 整数（空でもよい） | いちばん長いコンボ |
| `rewarded` | 真偽（初めは偽） | ごほうびを出した回か |
| `created_at`・`updated_at` | | |

索引: `user_profile_id`・`game`・`played_on` の組。

### 5-2. ごほうび

- その日（`Garden::today()`）にそのゲームを終えた回のうち、最初の3回（`daily_rewarded_plays`）にごほうびを出す。正解が0でも1回と数える（「1日3回まで」を分かりやすくするため）
- ごほうび = 正解の数 × 3-3の1問あたりの値。`UserProfile::applyEconomy(['xp' => …, 'point' => …], 'game_catch')` で出す（お金の記録に1行残る）。正解が0なら記録しない
- レベルが上がったら、結果の画面で今のレベルアップの画面（`LevelUpOverlay`）を出す
- HP・コイン・プロフィールのコンボ・毎日の連続・相棒のなかよし度・畑の水やりは動かさない

### 5-3. 自己ベスト

難しさごとに、終えた回の `score` のいちばん高い値。

## 6. サーバー

### 6-1. 設定（`config/games.php`、新規）

```php
return [
    'catch' => [
        'category' => '英語を学ぶ',
        'question_count' => 10,
        'review_max' => 6,
        'daily_rewarded_plays' => 3,
        'score' => ['correct' => 10, 'combo_bonus' => 5, 'combo_bonus_from' => 3],
        'difficulties' => [
            '初級' => ['lanes' => 2, 'fall_ms' => 8000, 'max_label_width' => 16, 'reward' => ['xp' => 3, 'point' => 3]],
            '中級' => ['lanes' => 3, 'fall_ms' => 6000, 'max_label_width' => 14, 'reward' => ['xp' => 4, 'point' => 3]],
            '上級' => ['lanes' => 4, 'fall_ms' => 4500, 'max_label_width' => 12, 'reward' => ['xp' => 5, 'point' => 3]],
        ],
    ],
];
```

列の数と落ちる時間は、始めるときの返事で画面に渡す。画面には数字を持たせない。

### 6-2. 計算（`app/Support/CatchGame.php`、新規）

- `summary(UserProfile $profile): array` — 難しさごとの「使える問題の数」「自己ベスト」と、今日のごほうびの残り回数
- `start(UserProfile $profile, string $difficulty): array` — 4章のとおりに問題を選び、`profile_game_plays` に1行作って、問題と設定を返す
- `finish(ProfileGamePlay $play, array $answers): array` — 答えを採点し直し、点数・コンボを計算し、覚え具合に書き、ごほうびを出して、結果を返す
- `score(array $results): array` — 正解・まちがいの並びから、点数といちばん長いコンボを出す（3-5）

表のモデルは `app/Models/ProfileGamePlay.php`（新規）。`question_ids` は配列、`finished_at` は日時、`played_on` は日付、`rewarded` は真偽として扱う。

### 6-3. API

どれもログインが必要（`auth:sanctum`）。遊んでいるプロフィール（`ActiveProfile::find`）がなければ 422。

**`GET /api/games/catch`** — 難しさを選ぶ画面に使う

```json
{
  "category_id": 63,
  "difficulties": [
    { "difficulty": "初級", "lanes": 2, "available": 90, "best_score": 120 },
    { "difficulty": "中級", "lanes": 3, "available": 74, "best_score": null },
    { "difficulty": "上級", "lanes": 4, "available": 42, "best_score": null }
  ],
  "rewarded_plays_left": 2
}
```

**`POST /api/games/catch/plays`** — 始める。`difficulty` は初級・中級・上級のどれか（ほかは 422）

```json
{
  "play_id": 15,
  "difficulty": "初級",
  "lanes": 2,
  "fall_ms": 8000,
  "questions": [
    {
      "id": 947,
      "prompt": "「tired」の意味は？",
      "choices": [{ "id": 3801, "label": "元気な" }, { "id": 3800, "label": "疲れた" }],
      "correct_choice_id": 3800
    }
  ]
}
```

使える問題が0問なら 422（「アメリカかイギリスに着くと遊べるよ」。中級・上級だけ0問のときは「この難しさの問題はまだないよ」）。

**`POST /api/games/catch/plays/{play}/finish`** — 終える

送るもの: `answers`（答えた順の `{ question_id, choice_id }` の配列。答えた数だけ。0個でもよい）

- 次のときは断る
  - その回が、遊んでいるプロフィールのものでないとき（404）
  - もう終えた回のとき（409）
  - `question_id` がその回で出した問題でないとき、同じ問題が2回あるとき、`choice_id` がその問題の選択肢でないとき、出した問題の数より多いとき（422）
- 採点は選択肢の `is_correct` で行う

```json
{
  "answered_count": 10,
  "correct_count": 8,
  "score": 100,
  "best_combo": 6,
  "best_score": 120,
  "new_best": false,
  "reward": { "xp": 24, "point": 24 },
  "rewarded_plays_left": 1,
  "leveled_up": false,
  "previous_level": 3,
  "level": 3
}
```

ごほうびがない回は `reward` を `null` にする。`previous_level` は終える前のレベル（レベルアップの画面で、新しく買えるようになった物を出すのに使う）。

### 6-4. 覚え具合（`app/Support/QuestionMemory.php`）

- `record` で、まちがえたら `wrong_on` に今日を、正解したら空を入れる（4-4）
- 最近まちがえた問題の番号を、まちがえた日の新しい順に返す関数を足す（4-2の1）

## 7. 画面

### 7-1. 入口

- 学ぶタブの「ミニアプリ」の引き出しの一番上に「ゲーム」の段を足し、「スプルキャッチ」のボタンを置く（`/games/catch` へ）。その下に今のカテゴリーのボタンを並べる
- 「英語を学ぶ」の画面（`/play/[id]`）の難しさのボタンの下に、「スプルキャッチで遊ぶ」のボタンを置く。「英語を学ぶ」かどうかは、`GET /api/games/catch` の `category_id` と比べる

### 7-2. 難しさを選ぶ（`/games/catch`）

- スプルの絵、見出し「スプルキャッチ」、説明「落ちてくる答えを、スプルでキャッチしよう」
- 初級・中級・上級のボタン。それぞれに「2択」などの列の数と、自己ベストを添える。使える問題が0問の難しさは押せない
- 「今日のごほうび あと2回」。0回なら「今日のごほうびはおしまい。練習はいつでもできるよ」
- どの難しさも0問のとき（アメリカにもイギリスにも着いていない）は、ボタンの代わりに「アメリカかイギリスに着くと遊べるよ」と、「せかい」タブへのボタンを出す
- 遊んでいるプロフィールがないときは、ほかの画面と同じくプロフィール選びへ移る

### 7-3. ゲーム

縦長の画面（スマホの縦向き）を基本にする。パソコンでは真ん中に同じ幅で出す。上から次の順に並べる。

1. 上のバー: 「やめる」、何問目か（3/10）、点数、コンボ、ハート3つ
2. 問題文のカード（3-6）
3. 遊ぶ場所: 列に分けた縦長の場所。背景は、今は空から草地へのグラデーションと列の線（仮）。すみにスプルの成長の印（3-4）
4. 落ちてくる選択肢: 列ごとに、クリーム色の角の丸いカードに言葉を書く
5. スプル: 遊ぶ場所の下に、後ろ姿（`outing/back.webp`）で立つ。列を移るときは短く横に動く
6. 下のボタン: 「◀」「▶」（大きく、親指で押しやすい高さ）

- 「やめる」を押したら「やめる？ここまでの答えは残らないよ」と確かめ、はいなら難しさを選ぶ画面へ戻る
- ブラウザのタブを離れたら止め、戻ったら続ける（落ちている途中で見えないまま終わらないように）

### 7-4. 結果

- 点数、「正解 8/10」、いちばん長いコンボ。自己ベストを超えたら「新記録！」

### 7-5. 動きの作り

## 8. 画面の部品（ファイル）

```text
frontend/src/components/games/
  game-question.ts            問題の形（GameQuestion）と問題文の分け方（splitPrompt）。2本目以降も使う
  catch/catch-engine.ts       ゲームの動き（テスト付き）
  catch/catch-select.tsx      難しさを選ぶ画面
  catch/catch-game.tsx        ゲームの画面
  catch/catch-result.tsx      結果の画面
frontend/src/app/games/catch/page.tsx   選ぶ → 3・2・1 → ゲーム → 結果 を切り替える
```

問題の形:

```ts
export type GameChoice = { id: number; label: string };
export type GameQuestion = {
  id: number;
  prompt: string;
  choices: GameChoice[];
  correctChoiceId: number;
};
```

`catch-engine.ts` の主な関数:

| 関数 | すること |
|---|---|
| `createCatchGame(questions, { lanes, fallMs })` | 最初の状態を作る（1問目、スプルは真ん中、ハート3、点数0） |
| `moveBy(state, -1 or 1)`・`moveTo(state, lane)` | スプルを動かす。端より外には行かない。落ちている間だけ動ける |
| `tick(state, dtMs)` | 時間を進める。受け取る線に着いたら判定し、○×を見せる時間のあと、次の問題か終わりに移る |
| `growthStage(bestCombo)` | 成長の印（seed・sprout・bud・flower） |
| `answersOf(state)` | 終わるときに送る答えの一覧 |

状態の段階は、落ちている（`falling`）・○×を見せている（`feedback`）・終わり（`done`）の3つ。

## 9. 2本目以降のための共通の枠

| 共通にするもの | 1本目で作るもの |
|---|---|
| 問題の形 | `GameQuestion`（`game-question.ts`） |
| 遊んだ記録 | `profile_game_plays`（`game` の列でゲームを分ける） |
| 始める・終わるの形 | 「始めると1行作って問題と正解を返す → 終えると採点し直して記録・ごほうび」の流れ |

| 結果の画面 | スプルキャッチの結果の画面。2本目を作るときに、共通の部分を切り出す |

ゲームの動き（`catch-engine.ts`）は、ゲームごとに別に作る。2本目（うちゅう旅行）の「縦に流れる画面・左右の列」は、そのときに1本目と共通にできる所を切り出す。今は先回りして共通の部品を作らない。

## 10. テスト

### 10-1. サーバー（Pest）

- 使える問題: 選んだ難しさのステージの問題だけ、鍵の国の問題は出ない、選択肢が長い問題は出ない、4択以外は出ない
- 出す順: 最近まちがえた問題と復習の日が来た問題が先に入る。あわせて6問まで。10問まで。使える問題が10問より少なければその数
- 選択肢の数が、難しさの列の数と同じで、正解が1つ入っている
- 始めると `profile_game_plays` に1行でき、`question_ids` が返した問題と同じ
- 使える問題が0問なら 422。遊んでいるプロフィールがなければ 422。難しさが正しくなければ 422
- 終える: 採点し直した正解の数・点数・いちばん長いコンボ（3-5の例: コンボが3以上の正解に+5）
- 終える: ほかのプロフィールの回は 404、2回目は 409、出していない問題・同じ問題・ほかの問題の選択肢・多すぎる答えは 422
- 終える: 覚え具合に書かれる。まちがえると `wrong_on` が付き、正解すると空になる
- ごほうび: その日の1〜3回目に出て、4回目は出ない。日付が変わるとまた出る。正解0なら記録しない。HP とコインは変わらない
- 自己ベストと `new_best`
- クイズの答えでも `wrong_on` が付く・空になる（今の答えの API のテストに足す）

### 10-2. 画面（Vitest）

- `catch-engine`: 端で止まる、落ちている間だけ動ける、受け取る線で立っている列の言葉を受け取る、正解・まちがいの点数とコンボとハート、ハート0で終わる、10問で終わる、○×を見せる時間、1回に進める時間の上限、`answersOf`
- `growthStage` の境目（2→3、5→6、9→10）
- `splitPrompt`: 「」で始まる文、文法の文、「」で始まらない文
- 点数の決まりが、サーバーのテストと同じ例で同じ値になる

### 10-3. ブラウザでの確認

- スマホの幅で、初級・中級・上級を1回ずつ遊び、落ちる速さ・文字の大きさ・ボタンの押しやすさを見る
- まちがえた問題が次の回に先に出る
- 4回目にごほうびが出ない
- 確かめたあと、開発用のデータを元の状態に戻す
