# 街づくりのCanvas化(全体の流れと段階1)— 設計書

- 作成日: 2026-10-19
- ステータス: **案(Ownerの確認待ち)**。段階1の中身(4章以降)の確認がとれたら、実装計画に進む
- ブランチ: `feature/town-canvas`(長くかかるので、mainとは分けて進める。段階ごとにmainへ入れるかは、段階の終わりにOwnerと決める)
- きっかけ: Ownerの提案(2026-10-19)。Codexが作った試作 `showcases/spraworldsample/`(Canvas 2D)が、街づくりの課題の解決に向いている。Spra Worldと同じ絵を使えるので、Spra Goで試したことをSpra Worldへ戻せる
- Owner決定: **全体を4段階で、順番に進める。「レベルで区画が開く仕組み」は残す**

## 1. 目的

- 街づくりを、「置くだけ」から、「道を引く・歩く・育てる」遊びに広げる(試作のよいところ)。
- 描き方を、SVGからCanvasにする。町が広く・物が多くなっても、軽く動くようにする。
- 試作の絵・考え方を、Spra World(`projects/Spra-world`)と共有できる形にする。

## 2. 試作でわかったこと(読んだ結果)

- マスの大きさは、今のSpra Goと**同じ**(幅64・高さ32の2:1)。座標の計算(`tileCenter`・`depthTile` など)は、そのまま使える。
- 試作は、地面・道路を1回だけCanvasに描いて使い回し、動くもの(木・建物・Spru)だけを毎フレーム描く。奥から手前の順に重ねる。
- 試作は、本番に足りないものがある: データはlocalStorage / 建物は固定 / 区画・レベル・雲の解放なし / 夜・季節・仲間・畑・吹き出しなし / 画面を読み上げる仕組みなし。
- 試作の建物は長方形(3×2など)も使う。今のSpra Goは**正方形だけ**(1〜3)。

## 3. 全体の4段階

| 段階 | 内容 | 遊びの変化 | データ(サーバー)の変化 |
|---|---|---|---|
| **1** | 描き方だけCanvasにする | なし(見た目も同じ) | なし |
| 2 | 道を自由に引く。Spruが歩く。カメラ(動かす・拡大)をCanvasの中に持つ | あり | 道のテーブルを足す |
| 3 | 地図の広さ・区画を作り直す(区画をレベルで開く仕組みは残す) | あり | 区画の設定が変わる。置いた物の座標は新しい地図に移す |
| 4 | 長方形の建物・家のレベルごとの敷地と地面 | あり | 建物の大きさの決まりが変わる |

- 段階ごとに、設計書→実装計画→実装→Ownerが画面で確認、の順で進める(この設計書は、全体と段階1)。段階2以降は、段階1の結果を見てから書く。
- 段階1の終わりは、段階2を始めなくても、そのまま使える状態にする(止められる)。

## 4. 段階1の方針

**町の絵だけを、SVGからCanvasに入れ替える。** 画面の外から見たものは、変えない。

- `WorldScene` の**引数(props)は変えない**。`world-screen.tsx` ほか、呼ぶ側は直さない。
- 町の地図の枠(`TownMap`。スクロール・ボタンで拡大・ピンチ)も、段階1では**今のまま**。カメラをCanvasの中に移すのは段階2(道を引くときにドラッグを使うため)。
- 押せる場所(アイテム・家・畑・仲間・スプル・雲の札・置く場所のマス)の**透明なボタンと吹き出し・札は、今のHTMLのまま**重ねる。キーボードと読み上げ(`aria-label`)が、そのまま使える。Canvasの自前判定は、段階2で道を引くときに入れる。
- 切り替えの安全のため、**開発中は、SVG版とCanvas版を両方持つ**。ふだんはSVG版が出て、URLに `?canvas=1` を付けるとCanvas版が出る。Ownerが見比べて「同じ」と確認できたら、Canvas版をふつうにして、SVG版を消す。

## 5. 作るもの(`frontend/src/components/world/canvas/`)

| ファイル | 内容 | テスト |
|---|---|---|
| `scene-model.ts` | propsから、描くものの一覧を作る純粋な関数。奥から手前の並び・絵の位置と大きさ(`imagePlacement`)・影・夜の光の輪・畑の絵・スプルと仲間の絵の位置。**SVG版と同じ計算を使う**(重複させず、`land.ts`・`item-image.ts` を共用) | Vitest |
| `animation.ts` | 時間から、動きの量を出す純粋な関数。`spru-bob`(2.4秒・上下3px)、`spru-hop`(0.9秒×2回)、`tile-pulse`(1.1秒・透明度0.55↔0.95)、`pop-in`(0.45秒)、`cloud-clear`(1.2秒)、波の縁(`town-foam`)。CSSの動きと同じ値にする | Vitest |
| `image-cache.ts` | 画像を読み込んで、すべて揃ってから描く。読み込めない絵は、SVG版と同じ代わりの絵(プレゼント箱) | Vitest(読み込みの管理だけ) |
| `draw-ground.ts` | 動かない層。波の縁・崖・区画の地面の絵(4×4マスの菱形に変形)・市松・道・道のふち・中央線と横断歩道・林と花畑の溶け込み・小物・夜の色。**変わったときだけ**描き直す | 画面の比較 |
| `draw-objects.ts` | 動く層。奥から手前へ、目印・アイテム・仲間・スプル・畑・光の輪・「！」・相棒の札・「zzz」・置くときのうす絵。置ける場所とプレビューのマス、雲 | 画面の比較 |
| `town-canvas.tsx` | CanvasのReact部品。大きさ(枠の幅×縮尺×画面の密度、最大2倍)の管理、`requestAnimationFrame`の描き直し、画面が見えないとき・動きを減らす設定のときは止める | 画面の比較 |

- 動かない層は、別のCanvasに描いて保存(キャッシュ)し、毎フレームは貼るだけにする。変わったとき(道・アイテム・区画・時間帯・読み込み)だけ作り直す。
- 動く物がない間は、描き直しの頻度を落とす(動いているのは、スプル・仲間・光る場所・波だけ)。

## 6. SVGからCanvasへ移すもの(漏れ防止の一覧)

動かない層: 波の縁(2本・ぼかし)/ 崖の岩肌(左右。右は暗く重ねる)/ 区画の地面の絵 / 絵のない地面の市松 / 道のマス・道のふち・色の帯・中央線・横断歩道 / 林・花畑(ぼかしの切り抜き)/ 小物 / 夜の色。
動く層: 畑の光 / 置ける場所の光 / 置く前のプレビュー / 雲(区画の形で切り取り。開いた直後の晴れる動き)/ 目印・アイテム(置いたときの「ぽん」、夜の光の輪、左右反転)/ 仲間(タップで跳ねる、相棒の札、「！」)/ スプル(上下・跳ねる、つぼみ・花、「！」)/ 家の「zzz」。
**HTMLのまま**: 透明なボタン・雲の札・吹き出し・海の背景・夜の暗さ(海と地図枠)。

## 7. 確認の方法

- 動かないものと動くものの計算(`scene-model`・`animation`)は、Vitestで確かめる。SVG版が作る位置・大きさと**同じ値になる**ことを、いくつかのデータ(家・大きな建物・反転・夜・開いた区画/雲)で比べる。
- 画面は、Playwrightで、**同じデータのSVG版とCanvas版の写真をとって見比べる**。昼・夕方・夜、雲あり、置くとき(プレビュー)、仲間あり、家族の町(見るだけ)。違いは1つずつ直す。
- 軽さ: 今のSVG版と、スクロール・拡大中のフレームの時間を比べる(数値で記録)。遅くなったら、そこで止めて直す。
- 既存のテスト(Vitest・Pest)がすべて通ること。

## 8. 危ないところ

- 画像がまだ読み込めていない瞬間に描くと、物が抜けて見える。→ 全部読み込めてから最初を描く。途中で増えた絵は、読み込めたら描き直す。
- 画面の密度(スマホの2〜3倍)で、Canvasが大きくなりすぎる。→ 密度は最大2倍にし、大きさの上限も決める(幅4096px以内)。
- 夜の暗さ・光の輪は、SVGの `filter` を使っている。→ Canvasでは、描くときに明るさを下げる。見た目が違えば、その場で合わせる。
- SVG版とCanvas版を両方持つ間は、直しが二重になる。→ 段階1のうちに切り替えを終える。

## 9. やらないこと(段階1)

- 道を引く・Spruを歩かせる・Canvasの中でのタップ判定・カメラ(段階2)。
- 地図の広さ・区画・アイテムの座標の変更(段階3)。
- 長方形の建物(段階4)。
- 新しい絵・音・サーバーの変更。

## 11. 実装の記録(2026-10-19)

- 実装: `frontend/src/components/world/canvas/`(`scene-model`・`animation`・`image-cache`・`draw-ground`・`draw-objects`・`town-canvas`)。`world-scene.tsx` は、`?canvas=1` のときだけ `TownCanvas`(`?canvas=0` で戻す。この端末に覚える)。
- 見比べ(Playwright。SVG版とCanvas版の写真の、色の違いの平均。0〜255): 夕方・雲あり 0.9 / 昼・仲間あり 3.8 / 夜・アスファルトの道 2.7 / 置く場所・プレビュー 1.5〜1.9(置く場所の点滅の位相の差を含む)。物の位置・大きさ・前後・夜の暗さ・光の輪は一致。
- 直したこと: 夜の色が、側面と陸の重なる所で二重に濃くなった(SVGの `<g opacity>` と同じに、1回だけ重ねる)。
- 軽さ(ヘッドレス、64個のアイテム、3秒): CPU 時間 SVG 51% → Canvas 31%、スクリプト 23% → 17%。フレーム率は同じくらい(50 → 45。測るときのばらつき内)。
- まだ見ていないもの: 開いたばかりの雲が晴れる動き(動きの計算はテスト済み)、実機のスマホ。
- Ownerが `?canvas=1` で見比べ、「見た目は同じ」と確認(2026-10-19)。**Canvas版をふつうにし、SVG版・切り替え(`?canvas`)・使わなくなった部品(`garden-art`・`landmark-art`)を消した**。家族の町(見るだけ)で畑の光を出さない決まりを、モデルの `readOnly` に移した(テスト追加)。
