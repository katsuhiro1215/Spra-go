# Tane の同意のしなおし対応（Tane 側からの回答）

- 作成: 2026-10-23（Tane 側のチャットから）
- 依頼文: `2026-10-23-tane-terms-consent-request.md` への回答

## 結果

**対応ずみ。** 依頼の2章の4項目に対応した（実装計画: `docs/superpowers/plans/2026-10-23-tane-terms-consent.md`）。

1. 同意の画面（Tane で完結）。ログイン・登録の返事の `user.terms_outdated` を見て、古ければプロフィール選択の前に `/account/terms-consent` へ送る。中身は依頼文の文言どおり（見出し・要約4行・全文へのリンク2つ・「同意する」「同意しない」）。「同意する」は `GET /api/user` で取った `terms_version_current` を使って `POST /api/terms/accept` を呼び、成功したらプロフィール選択へ進む。422（版がずれた）は「もう一度、この画面をひらきなおして」と案内する。「同意しない」は既存のログアウト処理（トークン・端末の記録を消す）を実行し、「アカウントの削除は info@spra.jp へ」と案内する（遷移はしない）
2. 403 `code: "terms_outdated"` も、同じ画面へ送る。Taneの入口（進み具合の取得・保存、保護者の記録）のこの403を検知する箇所（同期の仕組み・保護者の画面）を、既存の「プロフィールが消えた」403とは `code` の有無で区別するように直した。同意が古いときは、プロフィール・未送信の記録は外さない・消さない（同意後に送り直す）
3. Tane専用の規約・プライバシーのリンクを、共通版（`https://go.spra.jp/terms`・`/privacy`）に置き換えた（登録画面・同意しなおし画面）。Tane専用の下書き（`company/spra/tane/docs/legal/`）には、ログイン有効化時は本文を持たずリンクに置き換える旨を追記した（補足が必要になった場合は、そのとき短い補足を残す形にする）
4. 登録画面の同意チェック文を「利用規約とプライバシーポリシーに同意します」に変更した

## 確認した内容

- ローカルで `GET /api/auth/token`・`GET /api/user`・`POST /api/terms/accept`・`/api/tane/profiles/{id}/progress` の応答をスタブして確認:
  - ログインの返事が `terms_outdated: true` のとき、プロフィール選択の前に同意画面に送られ、同意すると進める
  - `terms_outdated` が無い（古い Spra Go の返事）ときは、同意画面が出ずそのままプロフィール選択に進む
  - プロフィール選択後、進み具合の取得で403 `code: "terms_outdated"` が返ると、同意画面に送られる
  - 登録画面の文言・リンク先が依頼どおりになっている
- 既存の vitest（422件）・tsc・eslint は壊れていない

## 見つかった問題

- 大きな問題は無い。確認作業では、同意する版の値（`version`）が `POST /api/terms/accept` の入力には必要だが、ログイン・登録の返事には含まれていなかったため、同意画面の表示時に `GET /api/user` を呼んで `terms_version_current` を取る形にした（依頼文にはこの経路の明記は無かったが、仕様から自然に導けた）。Spra Go 側の実装と合っていることを、本番相当のやりとりで確認いただけると安心です

## このあとの流れ（Spra Go 側にお任せする分）

依頼文4章のとおり。規約の本文を確定（専門家の確認）→ Spra Go で版を上げてデプロイ → 同意の画面を実機で確認 → `TANE_LOGIN_ENABLED=true`・`NEXT_PUBLIC_TANE_LOGIN=on`（Taneの再ビルド）。Tane 側はいつでも受け入れられる状態です。
