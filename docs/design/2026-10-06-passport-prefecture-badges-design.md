# パスポートの「日本のバッジ」（都道府県クイズ 段階4）— 設計書

- 作成日: 2026-10-06
- ステータス: Owner合意済み（2026-10-06。案をチャットで示して承認）
- 前提: 都道府県クイズ（`docs/design/2026-10-05-prefecture-quiz-design.md` 7-3）、パスポート（`app/passport/page.tsx`・`GET /api/passport`）
- 対応するタスク: `TASKS.md` 都道府県クイズ 段階4

## 1. 目的

県のバッジ（上級のボスを全問正解でもらう称号「◯◯はかせ」）を、パスポートで、まとめて見られるようにする。もらった数が分かり、まだの県のバッジも見えて、押すとその県のコースへ行ける。

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 場所 | パスポートの「獲得した称号」の下に、「日本のバッジ　12/47」。今の称号の一覧は残す |
| 並び | 6地方（北海道・東北／関東／中部／近畿／中国・四国／九州・沖縄）ごと。地方の中は、データ表の並び |
| 見た目 | もらった県はカラー、まだは白黒で薄く。県名を下に小さく。押すと `/play/{その県のコースの番号}` |
| 空のとき | 1つももらっていなければ、「県の上級を ぜんぶ正解すると、バッジがもらえるよ」 |
| 判定 | 称号「◯◯はかせ」を持っているか（今のプロフィールのもの。別のプレイヤーの称号は数えない） |

## 3. サーバー

`GET /api/passport` の返事に `prefecture_badges` を足す（今の項目は変えない。新しい表・窓口は作らない）。47件（データ表の並び）で、1件は `{ key, name, region, region_name, badge, earned, course_id }`。`course_id` は、その県のコース（`is_course_group` の地方カテゴリーの下の、県名のカテゴリー）の番号。見つからなければ null（画面は、押せないバッジにする）。作る部品は `App\Support\Prefecture\PrefectureBadges::list(array $titles)`（もらった称号の一覧を受け取る）。

## 4. 画面

- 純粋な関数（`lib/prefecture-badges.ts`）: `groupBadgesByRegion`（地方ごとにまとめる。地方の順は、返事に出てきた順）、`badgeCountText`（「12/47」）
- パスポートに、地方ごとの小さなバッジ（56px）を並べる。もらった県は `earned`、まだは `grayscale`＋`opacity-60`

## 5. テスト

- サーバー（Pest）: 47件・地方の順・称号を持つ県だけ `earned`・別のプレイヤーの称号は数えない・`course_id` が付く・今の項目が変わらない
- 画面（Vitest）: まとめる関数、数の文
- ブラウザ: パスポートで、地方ごとに並ぶ・もらった県がカラー・押すとコースへ・スマホ幅。確認のあと、プロフィール7を元に戻す

## 6. やらないこと

- パスポートの「日本 → 都道府県」の階層、バッジの拡大表示・説明
