# うちゅう旅行の改善(種を投げる・避けられない岩をなくす)— 設計書

- 作成日: 2026-10-19
- ステータス: **Ownerが方針を承認(2026-10-19。「種を投げて岩を壊す」「答えの門に投げて、待たずに答える」)**。細かい決めは12章
- 元の設計: `2026-10-09-space-trip-design.md`(この設計書は、3章「遊び方」と9章「テスト」を置き換える)
- きっかけ: Ownerの報告(2026-10-19)。(1)岩がよけられない場面がある(2列の初級)。(2)ロケットが門に着くまで待つのが無駄。「種を投げて岩を壊す」「種を投げて答えにする」案

## 1. 目的

- **避けようのない岩を、なくす**(バグ)。
- 種を投げる操作を足して、**待ち時間を遊びに変える**。岩を壊す・星を取る・答えを早く決める。
- サーバー(`CatchGame`・点数の計算・API)は変えない。画面側の動き(`space-engine.ts`)と画面だけの変更。

## 2. 原因: 避けられない岩

- 岩の段の間隔は、初級(2段)で進み0.133、中級・上級でも0.1〜0.13。岩に当たる範囲(`HIT_WINDOW`)は前後0.07ずつ(幅0.14)で、**段の間隔より広い**。
- 2列の初級で、上の段が左・下の段が右(など)に岩を置くと、2つの当たりの範囲が少し重なる。重なる間は、どちらの列にいても当たる。
- 3列・4列でも、「空いた列は段ごとにある」だけで、**段の間に列を移る時間が足りない**並びが出る。
- 設計書(元の3-3)の「どの段にも空いた列がある」は、1段だけを見た約束で、段をまたぐ動きを見ていなかった。

## 3. 遊び方(置き換え)

### 3-1. 操作

| 操作 | 内容 |
|---|---|
| 動く | ◀▶ボタン・列をタップ・キーボード ← →(今のまま) |
| **なげる** | **「なげる」ボタン**(◀と▶のあいだ)・キーボード スペース/↑。ロケットがいる列のまっすぐ上に、**種を1つ投げる** |

- 種は、約0.45秒で、いちばん上まで飛ぶ(進みとは別の時間で、実時間)。
- **連続では投げられない**。投げたあと、0.5秒のあいだ「なげる」は暗くなる(ためている)。数に限りはない。

### 3-2. 種が当たったときの動き

投げた種は、**その列で、いちばん近くのもの**に当たって、消える。

| 当たったもの | 動き |
|---|---|
| **隕石** | 隕石がこわれる(きらっと光る)。ぶつかったことにはならない。星は、ゼロにならない |
| **星** | 星を取ったことになる(ぶつかっていなければ、星+1) |
| **答えの門** | **その列の答えで、すぐに答えが決まる**。ロケットが門に着くまで待たない |
| なにもない | 上まで飛んで消える |

- 答えの門が見える(上から降りてくる)のは、**1問の途中から**(今のまま)。門が見える前は、種は門に当たらない。
- 早く答えたとき: 正解なら、すぐに○を見せて(0.8秒)、次の問題へ。まちがいなら、ハート−1・×を見せる(1.6秒)・正解の門を光らせる(今のまま)。
- **早く答えると、そのあとに来る星は、取れない**(速く進むか、星を集めるか、選べる)。そこまでに取った星は、点に入る。
- ロケットが門に着いて答える(今のやり方)も、残す。

### 3-3. 点数

今の決まりのまま(正解+10・コンボ3以上+5・星1つ+1。星は1問0〜3)。サーバーの計算も、APIの形(`answers[].stars` は0〜3)も変えない。早く答えても、点が増えることはない(星を取れないぶん、むしろ減る)。

### 3-4. 隕石の置き方(避けられない岩をなくす)

- 段の間隔の基本は、今のまま(0.3〜0.7に等間隔)。**そのうえで、置いたあとに、「よけられる道があるか」を調べる**。
- 道の調べ方(段ごとに、空いている列から、行ける列を絞っていく):
  - ある段の「いてよい列」= その段で、隕石のない列。
  - 次の段の「いてよい列」は、前の段のいてよい列から、**移れる**ものだけ。
    - 2つの段の当たりの範囲が重なっている(間隔が0.14未満)なら、**同じ列のまま**でないといけない(前も次も空いている列)。
    - 重なっていないなら、あいだの時間(ミリ秒)が、**列を移る時間以上**ならよい。列を移る時間 = 400ミリ秒 + 隣より遠い1列ごとに150ミリ秒。
  - 最後の段まで、「いてよい列」が残れば、よけられる。
- 置くとき、段ごとに乱数で置き、そこで道が切れるなら、その段をやり直す(最大20回)。それでも切れるなら、その段の隕石を減らす(0個にして終わる)。
- 隕石がよけられることは、**テストで、全部の種・全部の難しさ・全部の問題番号で確かめる**。

## 4. 画面

| 場所 | 内容 |
|---|---|
| ボタン | 下の段を3つに: ◀ / **なげる** / ▶ (まんなかを広く)。ためている間(0.5秒)は暗くなる |
| 種 | ロケットの先から上に飛ぶ小さな種(丸と芽の形。仮の図形)。種のあとに、短い軌跡 |
| こわれる隕石 | こわれた位置で、小さな破片と光(0.3秒) |
| 早く答えたとき | 種が当たった門が光る(正解は緑・まちがいは赤)。ロケットは、その場に止まる |
| 最初のヒント | 「◀▶で動く / なげる で岩をこわす・答えの門に当てて、すぐ答えよう！」(3・2・1のときに出す) |
| 音 | 投げる: `select`、隕石がこわれる: `coin`(小さく)、答え: 今のまま(`correct`・`incorrect`) |
| 動きを減らす設定 | 隕石は出さない(今のまま)。種を投げて答える操作は使える |

## 5. 仕組み(`frontend/src/components/games/space/`)

- `space-engine.ts`
  - `SpaceState` に `shots`(飛んでいる種: 列・位置・出た時刻)、`cooldownMs`、`blasts`(こわれた隕石の見た目: 列・隕石の着く時刻・残り時間)を足す。
  - `throwSeed(state)`: 進んでいる間・ためていないときだけ、種を足す。
  - `tick`: 進みとは別に、種を動かす(`SHOT_MS` で画面の上まで)。種が、ものの位置と**すれ違った**ときを当たりとする(前の位置と今の位置で、種の位置が、ものの位置をこえたとき)。1つの種は、いちばん近い1つに当たって消える。
  - 門に当たったら、`settle(state, lane, early)` で答えを決める。`early` のときは、`progress` を1にしない(その場で止める)。
  - `layoutFor`: 置いたあとに、`hasSafePath` で道を調べ、切れる段はやり直す(3-4)。`hasSafePath(items, lanes, fallMs)` を `export` して、テストが使う。
- `space-view.ts`: 種の位置(`itemFactor` と同じ座標)、ためている割合。
- `space-game.tsx`: 「なげる」ボタン・スペース/↑キー・種と破片の描画・ヒント。

## 6. テスト(`space-engine.test.ts` ほか)

- **よけられる**: 難しさ3つ × 種1〜200 × 問題番号0〜9 のすべてで、`hasSafePath` が真。さらに、道どおりに動くお手本の子(段の前に、列を移る)が、1回も隕石に当たらない(`layoutFor` + `tick` + `moveTo` の通し)。
- **種を投げる**: 投げると種が出て、0.5秒は次を投げられない / 隕石の列に当たるとこわれ、ぶつからない / 星に当たると星+1(ぶつかっていなければ)/ 当たらなければ消える / 別の列のものには当たらない。
- **早く答える**: 門が見えているとき、門に当たるとその列の答えが決まる(正解で+点・ハートそのまま、まちがいでハート−1)/ 門が見える前は当たらない / 早く答えたあと、星は増えない / 次の問題へ進んだとき、種・ためる時間が、リセットされる。
- **今のまま**: ロケットが門に着いて答える・点数・コンボ・星の数の範囲(0〜3)・動きを減らす設定。
