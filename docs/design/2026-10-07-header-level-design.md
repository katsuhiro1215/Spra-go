# ヘッダーのレベルの輪と「じぶんの状態」・ショップの表示の直し — 設計書

- 作成日: 2026-10-07
- ステータス: Owner合意済み（2026-10-07。8章の1〜3。レベルは100から始める）。実装計画に進む
- 前提: `docs/design/2026-09-27-spru-wave-b-design.md` 3-6（レベルの上がり方）、`docs/design/2026-09-28-app-chrome-design.md`（ヘッダー・下のメニュー）、`docs/design/2026-10-07-main-game-levels-design.md` 4-5（国レベル・言語レベル）

## 1. 目的

- ユーザーのレベルが、ヘッダーのどこにも出ていないため、ショップの「Lv.11で解放」が分かりにくい。自分のレベルと、あとどれくらいで上がるかを、いつでも見られるようにする。
- ヘッダーの右上（体力・連続日数・PT・コイン）が混み合っている。数字は必要なときだけ見られるようにして、すっきりさせる。
- スマホ幅（320〜375px）で、ショップの表示が崩れている（実際の画面で確認: 「ホームに戻る」が2行に折れ、「ショップ」の文字が縦に割れる）。

## 2. 3つのレベルの整理（画面でも、この言葉で分ける）

| 名前 | 何で上がるか | 何に使うか | 出す場所 |
|---|---|---|---|
| ユーザーのレベル（「レベル」） | 正解で貯まるXP | ショップ・町の区画の解放 | ヘッダーの輪、状態パネル、ショップの「Lv.◯で解放」 |
| 国レベル | その国のステージのクリア数 | 国ごとの進み具合 | パスポート、状態パネル |
| 言語レベル | 言語コースのステージのクリア数 | 言語ごとの進み具合 | パスポート、状態パネル |

## 3. 決定事項

| 項目 | 決定 |
|---|---|
| ヘッダーのレベル | レベルの数字を入れた丸い輪を出す。XPがたまると、輪が時計回りに伸びる（12時の位置から） |
| タップ | 輪をタップすると、「じぶんの状態」のパネルが下から出る（見るだけ。4章） |
| PT・コイン | ヘッダーでは**絵だけ**にする。数字は、状態パネルとショップで見る。パソコンではホバーの説明（`title`）も付ける |
| 体力ゲージ・連続日数 | そのまま |
| 下のメニュー「じぶん」 | 「持ち物と設定」にする。バッグ・パスポート・ずかん・**単語帳**・表示設定・プロフィール切り替え・ログアウト |
| 「学ぶ」画面の単語帳ボタン | そのまま残す（英語を学ぶ子が見つけやすい） |
| ショップ | 上に、PT・コインの2枚のカード（絵＋名前＋数字）を、タイトルの下に横並びで出す。ヘッダーの右上の置き方とは別 |
| レベルの上がり方 | 頭打ちをなくし、最初は緩やかに、だんだん重くする（6章）。レベルは下がらない |

## 4. 「じぶんの状態」パネル（輪をタップ）

下から出るシート（今の「じぶん」と同じ作り）。上から:

1. アバター・名前・レベル（大きく）。次のレベルまでの棒（「あと 120 XP で Lv.6」）
2. PT・コインの2枚のカード（絵＋数字）。連続日数
3. 国レベルと言語レベル（クリアの多い上位3つずつ。`GET /api/passport` の `country_levels`・`language_levels`。開いたときに読み込む）
4. 「パスポートを見る」ボタン

見るだけ。バッグなどの行き先は、下のメニューの「じぶん」に任せる（役割を分ける）。

## 5. ヘッダーとショップの作り

### 5-1. ヘッダー（`AppHeader`）

- 左: ロゴ（今のまま）。
- 右: 上の段に、レベルの輪と体力ゲージ。下の段に、連続日数・PTの絵・コインの絵（絵は小さな丸いバッジ。数字は出さない）。
- レベルの輪: 直径40px。SVGの円で、輪の伸びは `stroke-dasharray`。数字は輪の中。レベル2桁（10〜99）・3桁（100〜）でも収まる大きさにする。動きを減らす設定のときは、伸びのアニメーションをなくす。
- PT・コインの絵は、`aria-label`（「学習ポイント」「コイン」）を付ける。

### 5-2. ショップ

- 上: 戻るボタン、タイトル（1行）。その下に、PT・コインのカードを2列で並べる（絵・名前・数字。横幅が足りなければ縦に積む）。右上に置いていたバッジは、なくす。
- 戻るボタン（`BackLink`）は、折り返さず1行にする（`whitespace-nowrap`）。幅が足りない画面でも収まるように、必要なら文字を短くする。他の画面（単語帳・パスポート・ずかん…）でも同じ部品なので、同じ崩れが直る。

### 5-3. 下のメニュー「じぶん」

単語帳へのリンクを足す（バッグ・パスポートの並び）。

## 6. レベルの上がり方

- 次のレベルまでに必要なXP: `round5(100 + 10 × (L−1) + 0.5 × (L−1)²)`（L＝今のレベル。5の倍数に丸める）。頭打ちはなし。最初のレベルアップは100XP（初級の問題に10問正解）。
- 今の計算（100＋20×(L−1)、最大300）と比べて、Lv.10くらいまでは同じペース（少しだけ緩やか）で、そのあとは頭打ちがない分、だんだん重くなる。

| レベル | 次まで | そのレベルに届く合計XP |
|---|---:|---:|
| 1→2 | 100 | 100 |
| 2→3 | 110 | 210 |
| 5→6 | 150 | 615 |
| 10→11 | 230 | 1,590 |
| 15→16 | 340 | 3,055 |
| 20→21 | 470 | 5,130 |
| 30→31 | 810 | 11,620 |
| 50→51 | 1,790 | 37,450 |

（今の計算では、Lv.6＝700・Lv.11＝1,900・Lv.21＝4,900・Lv.31＝7,900。新しい計算は、Lv.11までは今より少し早く届き〔1,590〕、Lv.21は今とほぼ同じ〔5,130〕。そのあとは今より重くなる）

- 「レベルは下がらない」の決まりは、そのまま。保存してあるレベルより低くなる間は、今のレベルのまま。
- ショップの解放レベル（最大15）・町の区画（最大10）は、今のまま。
- 設定は `config/world.php` の `level_curve`（`base`・`linear`・`square`・`round`）で変える。

## 7. テスト

- サーバー（Pest）: 新しい計算（上の表の値、頭打ちがないこと、`levelForXp` と `totalXpFor` が一致すること、保存レベルより下がらないこと）。既存のレベル関連のテストを、新しい数字に直す。
- フロント（Vitest）: 輪の伸び（XPの割合から、輪の長さを返す関数。0%・50%・100%・次のレベルに届いた直後）、パネルの「あと◯XP」の計算。
- ブラウザ: 375px・320px で、ヘッダー・状態パネル・ショップ・戻るボタン・下のメニューの「じぶん」。確認後、確認用のアカウントを消す。

## 8. 確認してほしいこと

1. **レベルの上がり方（6章）**: Ownerの指定で、100から始めて、だんだん重く（頭打ちなし）にした。数字はこれでよいか。
2. **状態パネルの中身（4章）**: 足したい・減らしたいものがあるか。
3. **ヘッダーの右の並び（5-1）**: 上の段に「輪＋体力」、下の段に「連続日数・PT・コインの絵」。この置き方でよいか。

## 9. やらないこと

- 町の画面の上のバー（レベルのバー）の作り直し。
- ショップの商品の並び・解放レベルの見直し。
- レベルアップの演出（ポップアップなど）。

## 10. 実装の順序（実装計画で細かくする）

1. レベルの上がり方（サーバー）。
2. ヘッダー（輪・絵だけのPT・コイン）と状態パネル。
3. ショップの表示と、戻るボタン。
4. 下のメニュー「じぶん」に単語帳。
5. 確認（375px・320px）、SPEC・TASKS の更新。
