# ミニゲームの小出し（出す日・NEW・今週のゲーム・季節・ごほうびの上限）— 設計書

- 作成日: 2026-10-09
- ステータス: 設計中（方針はOwner合意済み 2026-10-09: 常設＋新登場＋週替わり＋季節。消えるのは季節だけ）
- 前提: ミニゲーム（`docs/design/2026-09-29-spru-catch-design.md` ほか）。`config/games.php`、`app/Support/CatchGame.php`、ミニアプリの一覧 `frontend/src/lib/mini-app.ts`

## 1. 目的
ミニゲームを、公開後に1本ずつ足して、飽きずに遊び続けられるようにする。

1. 先に何本か作っておき、**決めた日に自動で出る**（そのたびに配信し直さない）
2. 出たばかりのゲームは**「NEW」**と**お知らせ**で気づける
3. 週ごとに**「今週のミニゲーム」**を1本選び、ごほうびを少し増やす
4. 季節のゲーム（ハロウィンなど）は、**その時期だけ**出す
5. ゲームが増えても、**1日のごほうびの合計**が増えすぎない

**うまくいった目安**
- 出す日の前は、一覧にも出ず、遊ぶAPIも使えない。日が来ると、プレイヤーの一覧に出る
- 新しいゲームは、遊ぶまで、または14日たつまで「NEW」が付く
- 今週のゲームは、毎週決まった1本。ごほうびが1.5倍
- 季節のゲームは、期間の外では出ない（毎年くり返す）
- 全ゲームの合計で、1日にごほうびが出る回数に上限がある

## 2. 決定事項
| 項目 | 決定 |
|---|---|
| 常設 | 今の3本（スプルキャッチ・こっき・うちゅう旅行）。出す日なし・季節なし |
| 新登場 | `released_on`（出す日）から14日間（`new_days`）。その子がまだ遊んでいないあいだだけ「NEW」。そのあとは常設と同じ |
| 出す日の前 | 一覧に出ない。ゲームのAPIは404。出す日は設定ファイルで決める（配信し直さなくても、日付で出る） |
| 季節 | `season: ['from' => 'MM-DD', 'until' => 'MM-DD']`（毎年）。期間の外は、一覧に出ず、APIは404。年またぎ（12-20〜01-05）も可 |
| 今週のミニゲーム | 出ているゲームのうち、季節でないものを、週（月曜はじまりの週番号）で順に1本選ぶ。ごほうびを1.5倍（切り上げ）。季節のゲームがあるあいだは、季節のゲームを今週のゲームにする |
| ごほうびの上限 | 全ゲームの合計で、1日6回（`games.daily_rewarded_total`）。ゲームごとの3回は今のまま。どちらか先に尽きたら、ごほうびなし（練習）になる |
| お知らせ | アプリの中だけ（端末のプッシュ通知はしない）。学ぶ画面に「◯◯が出たよ！」のカード（遊ぶか、×で消す）。ミニアプリの一覧に「NEW」「今週」「きせつ」の札 |
| 消えるゲーム | 季節だけ。それ以外は消さない |

## 3. 設計
### 3-1. 設定（`config/games.php`）
各ゲームに `catalog` を足す。

```php
'space_trip' => [ ..., 'catalog' => ['released_on' => null, 'season' => null] ],
```
全体: `'rollout' => ['new_days' => 14, 'daily_rewarded_total' => 6, 'featured_multiplier' => 1.5]`

### 3-2. 出し分け（`app/Support/GameRollout.php`・新規）
- `GameRollout::available(?string $today = null): list<string>`: 今日出ているゲーム（出す日が来ていて、季節の中）
- `GameRollout::featured(?string $today): ?string`: 今週のゲーム
- `GameRollout::isNew(UserProfile, string $game, ?string $today): bool`
- `GameRollout::list(UserProfile): list<array{game, key, new, featured, seasonal}>`
- `GameRollout::assertAvailable(string $game)`: 出ていなければ 404

### 3-3. API
- `GET /api/games`: `GameRollout::list`（出ているゲームだけ。順番は設定の順）。フロントの一覧の元
- 既存の `games/{path}/*`: 先頭で `assertAvailable`
- ゲームの `summary`（`GET /api/games/{path}`）に `featured` を足す（画面の札用）

### 3-4. ごほうび（`CatchGame`）
- `rewardedPlaysLeft`: `min(ゲームの残り, 全体の残り)`。全体の残り = 6 − 今日終えた回の合計
- ごほうびの量: 今週のゲームなら、xp・pointを×1.5（切り上げ）

### 3-5. 画面
- ミニアプリの一覧（`frontend/src/lib/mini-app.ts` の `MINI_GAMES`）: タイトル・説明・URLはフロントに持ち、**出ているか・NEW・今週・きせつ**は `GET /api/games` の答えで決める。API にないゲームは出さない
- 学ぶ画面: NEWのゲームがあれば、「新しいミニゲーム ◯◯が出たよ！」のカード（遊ぶボタンと×）。×は、ゲームごとに端末に覚える
- ゲームの画面: 今週のゲームなら「今週のミニゲーム！ごほうび1.5ばい」の札

## 4. テスト
- Pest（`GameRolloutTest`）: 出す日の前後／季節の期間の内外（年またぎも）／今週のゲームが週で変わる・季節があれば季節が優先／NEWは遊ぶと消える・14日で消える／一覧のAPI／出ていないゲームのAPIは404／全体の上限（3+3で6回になると、3本目はごほうびなし）／今週のゲームのごほうび1.5倍
- Vitest: 一覧の組み立て（APIにあるゲームだけ・札）／お知らせカードの表示と×の記憶
- 確認: スマホ幅（375px）で、学ぶ画面とミニアプリの一覧

## 5. やらないこと
- 端末へのプッシュ通知（アプリ化のとき）
- 管理画面から出す日を変えること（今は設定ファイル。必要になったら）
- 新しいミニゲームそのもの（別の作業。このしくみに、1本ずつ載せる）
- 期間限定の景品・実績

## 6. 実装の順序
1. 設定と `GameRollout`（テスト付き）
2. ゲームのAPIの出し分け・`GET /api/games`・全体の上限・今週のごほうび
3. フロント（一覧・NEW札・お知らせカード・今週の札）
4. 確認、SPEC・TASKS
