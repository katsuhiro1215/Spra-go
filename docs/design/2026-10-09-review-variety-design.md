# 復習の変化（スペルを並べる形・覚え具合の演出）— 設計書

- 作成日: 2026-10-09
- ステータス: Owner合意済み（2026-10-09。音声は今はやらない・英語のゲームだけで始める・復習の演出も一緒に。8章はすべて私のおすすめで決定）
- 前提: 問題ごとの覚え具合（`docs/design/2026-09-29-spaced-review-design.md`。段階1〜5・出す日・まちがえた日）、英語の単語の問題（`docs/design/2026-10-07-english-levels-design.md`。`questions.meta` に `kind`・`word`・`word_id`・`direction`）、単語帳（`docs/design/2026-10-07-word-book-design.md`）
- きっかけ: Codexの指摘（2026-10-09）。「4択に偏ると、答えではなく『見覚え』で正解できる」「繰り返しが作業に見える」。このうち「問題の形を増やす」と「復習の見せ方」を先に進める。回答時間・復習の滞留対策・音声は、あとの作業

## 1. 目的

1. 一度答えた英単語を、あとで**別の形（スペルを並べる）**で出して、見覚えだけでは答えられないようにする。問題の追加は要らない（今ある単語の問題を、遊ぶときに形だけ変える）
2. 復習で正解したときに、「前はまちがえたけど、今度はできた！」のように、**自分の成長が分かる一言**を出す

**うまくいった目安**

1. 英語のステージで、前に答えたことのある単語が、ときどき「文字のタイルを並べて書く」形で出る。初めて会う単語は、今までの4択
2. 答えは、元の単語の覚え具合に記録される（復習の予定はくずれない）
3. 復習で正解したとき、状況に合った一言（まちがえたあと・何日かぶり・あと1回で覚える・覚えた）が出る
4. ほかの問題（国・都道府県・宇宙・マッチングなど）は、今までどおり動く（一言の演出は、どの問題でも出る）

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 新しい形 | **スペルを並べる**。「『りんご』を英語で書こう」と出て、文字のタイルをタップして、枠に入れていく。キーボードは使わない（幼児・スマホ向け） |
| 音声 | 今はやらない（あとで、Web Speech APIで「音を聞いて選ぶ」を足す。この設計は、形を足しやすい作りにする） |
| 対象 | 英語の単語の問題（`meta.kind = word`）だけ。国・都道府県・宇宙は、あとで |
| 出す条件 | その子が**前に答えたことのある**単語だけ（覚え具合の記録がある問題）。初めて会う単語は、今までの4択 |
| 出す数 | 1ステージに最大2問（10問のうち2問まで）。続けては出さない |
| 単語の条件 | 英字だけ・3〜8文字（`words.key` が `^[a-z]{3,8}$`）。熟語・短すぎ・長すぎる語は、4択のまま |
| タイル | 単語の文字と、まちがいの文字（レベル10以下は1個、それ以外は2個）をまぜる。同じ文字が2つある語は、タイルも2つ |
| 答え方 | タイルを枠にタップで入れる。入れた文字をタップすると、もどる。「けす」で全部もどす。全部の枠が埋まったら「できた！」で答えを送る（自動では送らない） |
| 判定 | サーバー。大文字・小文字は区別しない。1回で決まる（体力・経験値・コンボ・連続などは、今までの答えと同じ） |
| 記録 | 元の問題（4択のほう）の覚え具合に書く。単語帳の「出会った語」にも、今までどおり入る |
| 解説 | 元の問題の解説を、そのまま出す。正解のスペルも出す |
| 復習の演出 | 答えの結果に、一言の札を出す（5章）。正解のときだけ。「練習」（やり直し）のときは出さない |

## 3. スペルを並べる形

### 3-1. 出し方（サーバー: ステージを取る窓口）

`GET /api/stages/{stage}` が、問題を返す直前に、`QuizVariants::apply` を呼ぶ（既存の `PlayableQuestion::present` のあと）。

1. 問題のうち、**単語の問題で、条件に合う**ものを探す（`meta.kind = word`・`meta.word` が `^[a-z]{3,8}$`・その子に、この問題の覚え具合の記録がある）
2. 合うものから、`max_per_stage`（2）まで、ランダムに選ぶ（同じステージの中で並びが続かないよう、2問が隣り合うときは、片方を4択に戻す）
3. 選んだ問題に、`variant` を足す:

```json
{
  "variant": {
    "kind": "spelling",
    "prompt": "「りんご」を 英語で かこう",
    "length": 5,
    "letters": ["p", "l", "a", "e", "p", "x", "t"]
  }
}
```

- `prompt`: `words.meanings` の最初の意味（`ja` の最初）を使って作る
- `letters`: 単語の文字と、まちがいの文字（`config('review.variants.spelling.extra_letters')`。レベル10以下は1個）をまぜて並べ替えたもの。まちがいの文字は、単語に含まれない文字から選ぶ
- 選んだ問題の `choices` は、空にして返す（4択の選択肢は出さない）。`type` は `multiple_choice` のまま（元の問題）
- 答えの文字の並び（正解）は、返さない（文字の数だけが分かる）

### 3-2. 答える

`POST /api/questions/{question}/answer` に、`spelling`（文字の文字列。例: `"apple"`）を足して送れる。

- `spelling` があるときは、`QuestionAnswerResolver::spelling` で判定する: 問題が単語の問題（`meta.word`）で、条件に合うときだけ。大文字・小文字を区別せず、`meta.word` と同じなら正解
- 返事は、今までの形（`correct`・`explanation`・`profile`・`word_id`）に、`correct_spelling`（正しい綴り）を足す
- 体力・経験値・コイン・ポイント・コンボ・連続・覚え具合・単語帳の出会いは、4択の答えと同じ処理を通る
- 練習（`practice`）でも、`spelling` を送れる（正解かどうかだけ返す）

### 3-3. 画面

- `SpellingQuestion`（`components/app/spelling-question.tsx`。並べ替え・仕分けの問題と同じ作り）: 枠（文字の数）・タイル・「けす」・「できた！」。答えたあとは、正解の綴りと、色（正解は緑・まちがいは赤）を枠に出す。まちがえたときも、正解の綴りが見える
- タイルは、大きく（タップしやすく）、折り返して並べる。枠が全部埋まるまで「できた！」は押せない
- `QuizQuestion` の型に `variant` を足す。`quiz-session.tsx` が、`variant.kind === "spelling"` のとき、問題文を `variant.prompt` に替えて、`SpellingQuestion` を出す
- 4択の答えの画面にある、答えのあとの解説・次へ・おすすめの仕組みは、そのまま使う

## 4. 覚え具合（記録）

- 4択と同じ `QuestionMemory::record` を通すので、記録の決まり（出す日より前の正解は段階が上がらない・まちがえると段階1・次の日）は変わらない
- スペルの形は、4択より難しいので、同じ「正解」でも重みは変えない（今は同じ。難しさで差をつけるのは、あと）

## 5. 復習の演出（覚え具合の一言）

### 5-1. 一言の種類

`QuestionMemory::record` が、答える前と後の覚え具合を比べて、`event` を返す。答えの窓口は、返事に `memory` を足す（正解のときだけ。練習・初めて会う問題は `null`）。

| `event` | 条件（優先の高い順） | 一言（画面） |
|---|---|---|
| `mastered` | 今回の正解で、「覚えた」になった | 「この問題を おぼえたよ！」 |
| `recovered` | 答える前の最後の答えが、まちがい（`wrong_on` がある）で、今回は正解 | 「前は まちがえたけど、今度は できたね！」 |
| `almost` | 今回の正解で、段階が上がって、段階5になった（覚えるまで、あと1回） | 「あと1回で マスター！」 |
| `returned` | 前に正解していて、前に答えてから3日以上あいて、今回も正解 | 「{n}日ぶりに 正解！」 |

- 初めて会う問題（覚え具合の記録がなかった）は、一言を出さない
- どれにも当てはまらない正解は、`null`（何も出さない）
- 日数は、日本時間の日付で数える（`Garden::today()`）

### 5-2. 画面

- 答えたあとの結果の部分（正解の演出・解説の近く）に、小さな札（バッジ）で一言を出す。スプルの声を足して、うれしい気持ちにする（今ある正解の演出を変えない）
- 4択・スペル・マッチングなど、どの形でも出る（答えの窓口が共通のため）

## 6. テスト

- サーバー（Pest）:
  - 出し方: 前に答えた単語だけが対象・初めての単語は4択のまま・1ステージ2問まで・隣り合わない・英字3〜8文字だけ・熟語や長い語は対象外・英語以外の問題は対象外・正解の綴りを返さない・タイルは単語の文字を含む・まちがいの文字は単語にない文字・レベル10以下はまちがいが1個。
  - 答え: 正解・大文字小文字・まちがい・対象外の問題への `spelling` は422・練習・記録（元の問題の覚え具合・単語帳・体力・経験値）。
  - 演出（`memory`）: `mastered`・`recovered`・`almost`・`returned`（3日以上・2日はなし）・初めては `null`・まちがいは `null`・練習は `null`。優先順。
  - 今までの4択・マッチング・並べ替えの答えは変わらない（既存のテスト）。
- 画面（Vitest）: タイルの入れ・もどし・けす・できたの出せる条件（純粋な部品）、一言の文言の組み立て。
- ブラウザ: スマホ幅で、英語のステージ（前に答えた単語がある状態）で、スペルの問題・正解・まちがい・一言の札を確かめる。確認用のプロフィールは、作って、確認後に消す。

## 7. やらないこと

- 音声（聞いて選ぶ）・キーボードでの文字入力・絵から選ぶ・英語以外の形の変更
- 仲間の反応（「前より速く答えられたね」）・回答時間
- 復習の滞留対策・苦手の優先（別の作業）
- 4択の問題そのものを減らすこと

## 8. 確認してもらったこと（私のおすすめで決定）

1. 初めて会う単語は4択のまま、**前に答えた単語だけ**スペルの形にする。
2. 1ステージに**最大2問**、続けない。
3. 答えは**「できた！」ボタンで送る**（自動で送らない）。
4. 一言は、`mastered`・`recovered`・`almost`・`returned` の4つ。

## 9. 実装の順序

1. サーバー: 覚え具合の変化（`record` が `event` を返す）と、答えの返事の `memory`。
2. サーバー: `QuizVariants`（出し方）・`QuestionAnswerResolver::spelling`・答えの窓口。
3. 画面: `SpellingQuestion`・`quiz-session` の組み込み・一言の札。
4. 確認と、SPEC・TASKSの更新。
