## 1. 背景と目的

未ログインのトップ（`components/app/guest-landing.tsx`）とプロフィール選び（`app/profiles/page.tsx`）には、まだ仮のキャラクター（`CharacterPlaceholder`、色違いの丸いキャラ）が出ている。トップは季節の風景の背景と前の配色のボタンのままで、ほかの画面の配色（時間帯の空・クリーム色・緑のボタン）とそろっていない。ブラウザのタブの題名も「Create Next App」のまま。

Ownerが用意したスプルの家の絵（`company/spra/mascot/assets/image1.png`）を真ん中に置き、入口の2画面をスプルの世界にそろえる。家の絵は町の目印の「スプルの家」と同じ家なので、入口と町の話がつながる。

## 2. 決定事項（Owner確認済み）

| 項目 | 決定 |

| トップの並べ方 | A案「家が主役」: 時間帯の空の上に、家と手を振るスプルを大きく置く。ボタンとお試しクイズも空の上に置く |

| 家の絵の使い道 | 入口（トップ・プロフィール選び）の「1枚の絵」としてだけ使う。町のマスには置かない（`company/spra/mascot/CLAUDE.md` 2026-09-28追記） |

## 3. トップ（`components/app/guest-landing.tsx` を作り直す）

- いちばん外側は `SkyPage`（時間帯の空）。季節の風景の背景（`SceneBackground`）と前の配色のボタン（`classic-button.tsx`）は、トップでは使わない（紹介ページ・Owner/管理のログインでは今のまま使う）
- 上: ロゴのマーク（`LogoMark`、40px）と「SpraGo」の文字（`h1`）。その下にキャッチコピー「学ぶほど、世界が広がる。」。文字は `SkyTitle`・`SkyText`（朝・昼・夕方はこげ茶、夜は白）
- 真ん中: スプルの家（新しい部品 `SpruHouse`、幅300px・スマホで画面からはみ出さない）。左下に手を振るスプル（`SpruFigure` の `wave`、少し上下に動く）を重ねる。どちらも開いてすぐ見えるので、遅れて読み込まない（`eager`）
- 下（上から）:
  - 「はじめる」（緑の大きいボタン、`AppButton` の `primary`）→ `/register`
  - 「アカウントをお持ちの方はログイン」（クリーム色の小さい札）→ `/login`
  - 「登録なしでお試しクイズ」の見出しと、日本・アメリカ・イギリス・フランスのスタンプの絵（パスポートのスタンプ `STAMP_IMAGES`、少し傾ける）と国名 → `/world/{code}`
- 画面の高さが低い端末では、縦にスクロールできる（家とボタンが重ならない）
- 右下の「文A」と音のボタンは、今までどおり出る（プレイヤーが入っていない画面のため）

### 3-1. タブの題名と説明（`app/layout.tsx`）

- 題名: 「SpraGo — 学ぶほど、世界が広がる。」
- 説明: 「言葉を学ぶと町が育ち、世界を旅できるようになる、家族で遊べる学習ゲーム。」
- ほかのページが自分の題名を決めている場合（`/world/[code]` など）は、そちらが優先される（今のまま）
- タブのアイコン・SNSで共有したときの画像は、Ownerの画像が届いてから入れる（この設計ではやらない）

## 4. プロフィール選び（`app/profiles/page.tsx` を作り直す）

- いちばん外側は `SkyPage`。上から:
  - 見出し「だれが冒険する？」（「冒険」にふりがな、今のまま）と、プレイヤーがいるときだけ「プロフィールを編集」（押すと「完了」に変わる）
  - スプルの家（`SpruHouse`、幅230px）
  - 家の前の芝生（上の辺がゆるく丸い緑の地面。画面の下まで続く）。芝生の上に、プレイヤーのアバター（丸い枠）と名前の札（クリーム色）が並び、最後に「＋ 追加」（点線の丸）を置く。横に並びきらない分は次の段へ
- アバターを押すと、そのプレイヤーで遊び始める（今までどおり、選んだら町へ）
- 「プロフィールを編集」中は、アバターの右上に鉛筆の印が付き、押すと編集のパネルが開く
- プレイヤーが0人のときは「まだプレイヤーがいません。最初のプレイヤーを作ろう！」と「＋ 追加」だけ
- 読み込み中は `SpruLoading`（今のまま）

### 4-1. 追加・編集のパネル（`components/app/profile-sheet.tsx`、新規）

- 下から出るパネル（`MeSheet` と同じ作り: Radix の Dialog、クリーム色、上の角が丸い、暗い幕）
- 追加のとき: 見出し「プレイヤーを追加」、「なまえ」の入力欄（例: お父さん）、「アバターをえらぶ」（6種を3×2で並べ、選んだものは緑の輪）、「追加する」
  - 最初から選んでおくアバターは、家族の中でまだ誰も使っていないものの1つ目。全部使われていたら1つ目
- 編集のとき: 見出し「プロフィールを編集」、名前とアバターは今の値から始める、「保存する」、いちばん下に「このプロフィールを削除」
  - 削除は確かめてから（Radix の AlertDialog。「〇〇を削除する？」「冒険の記録も消えます」「やめる」「削除する」）。今の `window.confirm` はやめる
- 名前が空のときは送らない（今のまま `required`）。サーバーのエラーはパネルの中に赤い文字で出す（「プロフィールの作成に失敗しました。」「通信エラーが発生しました。」など今の文言）
- 今の画面の下にある追加の入力欄と、その場で名前を書き換える欄は、このパネルに置き換えてなくす

## 5. アバターの保存（バックエンド）

- `user_profiles` に `avatar` 列（文字列、空でもよい）を足すマイグレーション。足すときに、今いるプレイヤーへ家族（`user_schema_id`）ごとに作った順（id順）で `avatar-1`〜`avatar-6` を割り当てる（7人目からはまた `avatar-1` から）。今の色違いの並び順と同じ
- 使える名前は `UserProfile::AVATARS = ['avatar-1', …, 'avatar-6']`。絵は画面側で対応させるので、絵を替えてもデータは変わらない
- `POST /api/profiles`: `avatar` は任意。送られたら `AVATARS` のどれかでなければ422。送られなければ、家族の中でまだ誰も使っていないものの1つ目（全部使われていたら `avatar-1`）
- `PATCH /api/profiles/{profile}`: 今の `name` に加えて、`avatar` も任意で受け取る（同じチェック）
- 一覧・選択・アクティブのAPIは、モデルの値をそのまま返すので `avatar` が増えるだけ
- 空いているアバターを選ぶ処理は `UserProfile` の静的メソッド（例: `nextAvatarFor(UserSchema $schema): string`）にして、APIとテストから使う

## 6. 絵の用意

### 6-1. スプルの家

- 切り抜きの道具（`tools/spru-assets/extract.py`）に、背景が透明でない絵のときは四隅から背景を抜く処理を足す（背景に近い色を四隅から塗りつぶして透明にし、ふちを少しぼかす）。もともと透明な絵ならこの処理は飛ばす
- `crops.json` に「house」の組を足し、image1 から家を切り抜いて `public/spru/house/home.webp` にする。`spru-assets.ts` に `HOUSE_IMAGES` が書き出される
- 画面では `SpruHouse`（`components/spru/spru-house.tsx`、新規。幅を決めて出し、高さは縦横の比から決める。`fixedImageSize` を使う）で出す
- 今夜、背景を消した家の画像が届いたら、`crops.json` の元の画像を替えて `extract.py` を流すだけで差し替わる

### 6-2. アバター

- 画面側の対応表 `components/app/avatars.ts`（新規）:
  - `AVATAR_KEYS`（サーバーの `AVATARS` と同じ6つ）
  - `avatarImage(key: string | null): SpruImage`（空・知らない名前は1つ目）
  - `firstUnusedAvatar(used: (string | null)[]): AvatarKey`（まだ誰も使っていないものの1つ目。全部使われていたら1つ目）
- 絵が届くまでの仮の絵: `avatar-1`〜`avatar-5` は仲間（Lumi・Momo・Kuru・Piko・Ruru）、`avatar-6` は笑顔のスプル
- 今夜の6種が届いたら、`crops.json` に「avatars」の組を足して切り抜き、対応表の中身だけ替える（データベース・ほかの画面は触らない）
- アバターは丸い枠（`AvatarBadge`、`components/app/avatar-badge.tsx`、新規。大きさを決めて、絵を枠の下にそろえて出す）で出す。プロフィール選びとパネルで使う

### 6-3. 仮のキャラクターの片付け

- トップとプロフィール選びから `CharacterPlaceholder` がなくなり、どこからも使われなくなるので、`components/app/character-placeholder.tsx` を消す。動きのクラス `animate-character-bounce`（`globals.css`）は、スプルの上下の動きで使っているので残す

## 7. テスト

### バックエンド（Pest）

- 追加: `avatar` を送るとその値で作られる／送らなければ家族で空いているものの1つ目／6つ全部使われていたら `avatar-1`／6種以外は422
- 変更: `avatar` を送ると変わる／6種以外は422／ほかの家族のプレイヤーは今までどおり403
- マイグレーションの割り当て: 家族ごとにid順で `avatar-1` から入る（割り当ての処理を関数にして、それをテストする）

### フロントエンド（Vitest）

- `avatarImage`: 6つの名前で別々の絵／空・知らない名前は1つ目の絵
- `firstUnusedAvatar`: 使われていないものの1つ目／全部使われていたら1つ目／空の値は「使っていない」扱い

### ブラウザでの確認（Playwright、390px と 1280px）

- ログアウトした状態でトップ: 家・スプル・コピー・ボタン・スタンプが崩れずに並ぶ。はじめる・ログイン・スタンプが正しいページへ行く。タブの題名が変わっている
- プロフィール選び: 家の前にアバターが並ぶ。仮のプレイヤーを追加（アバターを選ぶ）→ 編集（名前とアバターを変える）→ 削除（確かめてから）。最後に仮のプレイヤーが残っていないこと
- 開発用データベース: 列の追加は非破壊の `migrate`。確認のあと、町テスト（id 7）の値とおつかい（19・20・21だけ）が元のままであること

## 8. やらないこと

- トップの下の紹介の段（学ぶ→町が育つ→旅に出る、など）
- タブのアイコン・SNSで共有したときの画像（Ownerの画像待ち）
- 紹介ページ（`/world/[code]`・`/about`・`/blog`）とOwner/管理のログインの配色
- アバターを町・家族の町・ヘッダーなどほかの画面に出すこと
- 家の絵を町のマスに置くこと

## 9. 完了の条件

- トップとプロフィール選びが、この設計の並べ方になっている。仮のキャラクターがどこにも出ない
- プレイヤーごとにアバターを選べて、追加・編集・削除ができる。今いるプレイヤーのアバターの並びが変わらない
- バックエンド・フロントエンドのテスト、型チェック、lint が通る
- `SPEC.md`・`TASKS.md` に反映されている
