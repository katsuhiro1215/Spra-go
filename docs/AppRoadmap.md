# アプリ本体の実装状況とロードマップ

`docs/MVPRequirements.md`で決めたMVP範囲（日本/米国/英国/フランス、初級〜上級、無料公開）は内容としては揃った。しかし`docs/AppInfo.md`が掲げるサービス全体の構想と照らすと、アプリ本体（Webサイトのマーケティング面ではなくゲーム本体）にはまだ実装されていない要素が多く残っている。CEOとして現状を棚卸しし、優先順位をつける。

## 現状棚卸し（2026-07-29、CEO確認）

### ✅ 実装済み・MVPとして機能している

- 認証（Owner/Admin/User独立ログイン）、家族プロフィール（追加・選択）
- 国→難易度→ステージ→クイズの冒険ループ、正解/不正解演出
- 経済ロジック（HP/XP/Coin）、レベルアップ、難易度ロック（初級→中級→上級）
- ショップでの回復アイテム購入
- 称号（ボスステージクリア）
- 4ヶ国×3難易度、728問のクイズコンテンツ
- 公開マーケティングサイト（LP・国別お試しクイズ・ブログ・会社情報）

### ⚠️ 部分実装・機能しているが片手落ち

| 機能 | 現状 | 問題 |
|---|---|---|
| ショップ(コイン以外のアイテム) | `potion`（回復）のみ効果あり | `plane`/`background`/`character`/`title`タイプはOwnerが作成でき、購入もできるが**購入しても何も起きない**。ユーザーが混乱する |
| プロフィール | 追加・選択のみ | 名前変更・削除ができない。作り間違えても直せない |
| 地域階層（地方→都道府県→都市） | `Region`モデル・API・画面は実装済み | 実コンテンツは全て国レベルで作成しており、地域を使ったStageは実質0件（`docs/MainQuiz.md`が描いた「大阪だけで数百問」という深さは未着手） |
| イベント | Owner画面でイベントの作成・管理は可能 | プレイヤー側に表示する画面・APIが存在せず、**作っても誰にも見えない** |

### ❌ 未実装（`docs/AppInfo.md`の「🎮ゲーム要素 最重要要素」より）

- **コンボ（連続正解）**: AppInfo.mdが最重要要素の1つとして名指ししているが実装なし
- **ストリーク（毎日学習）**: 同上。継続ログインを促す仕組みが無く、DAU/リテンションに直結する要素が欠けている
- **コレクション/図鑑の集約ビュー**: 国ごとの達成率は表示されるが、「世界図鑑」として国旗・動物・食べ物などジャンル横断で集めた実績を一覧できる画面が無い（`docs/MVPRequirements.md`でMVPスコープ外と明記済みのものも含む）
- **国旗以外の入口**: `docs/AppInfo.md`は動物・食べ物・スポーツ・歴史・世界遺産・音楽など多様な入口を構想しているが、`Category`テーブルには器（ルートカテゴリー）だけあり中身のStageが無い

### 意図的にスコープ外（`docs/MVPRequirements.md`で確認済み、再掲）

AI問題生成・AI先生、有料メンバーシップ、パスポート専用画面、旅演出、フレンド機能・家族ランキング、学校/企業向けプラン、スマホアプリ化

## 優先順位（CEO判断）

1. **コンボ機能** — 最重要要素と明記されている割に工数が小さい（1回答APIと経済ロジックの拡張、フロント表示追加のみ）。次に着手する。
2. **ショップの未実装タイプを隠すか実装するか** — 中途半端な状態を残さない。まずは`potion`以外をOwner画面の選択肢から外し、実装が追いついてから再度開放する方が誠実。
3. **プロフィールの編集・削除** — 家族利用を謳う以上、最低限のCRUDは揃えるべき
4. **ストリーク（継続ログイン）** — コンボより設計判断（リセット時刻、タイムゾーン、猶予期間）が要るため次点
5. **イベント機能のプレイヤー向け実装、または一旦Owner画面から隠す** — 「作っても見えない」状態を解消
6. **地域階層・国旗以外の入口の拡充** — コンテンツ制作のボリュームが必要なため、中級/上級同様にコンテンツ制作担当と連携して計画する

## 追記(2026-07-29): コイン購入(Stripe)を追加

Ownerが開発用Stripeアカウントを用意し、`.env`に`STRIPE_PUBLIC_KEY`/`STRIPE_SECRET_KEY`を設定。これを受けてコインの実売購入機能を実装した。`docs/MVPRequirements.md`で「MVPは無料のみで先行公開」としていた方針からの変更で、Owner指示により対応。

- Stripe Checkout(決済ページはStripe側でホスト、カード情報は自社サーバーを一切通らない)
- 価格は`config/coin_packages.php`で一元管理(フロントから送られた金額は信用しない設計)。現在は100枚/¥120・550枚/¥500・1200枚/¥1000の仮価格
- `POST /api/coin-purchases/checkout`でCheckout Session作成 → Stripeの決済ページへ → `POST /api/stripe/webhook`(署名検証必須)で決済完了を受けてコイン付与。Webhookは`CoinPurchase.stripe_checkout_session_id`で二重付与を防止(冪等)
- 実際の開発用Stripeテストキーで疎通確認済み(sk_test_、本番キーではない)
- テスト7件追加(バリデーション・冪等性)。Stripe API自体は自動テストの対象外(手動確認のみ)

**未完了**: `STRIPE_WEBHOOK_SECRET`が`.env`に未設定のため、実際の決済完了→コイン付与までは通しで確認できていない。`stripe listen --forward-to <APP_URL>/api/stripe/webhook`実行時に表示される値を設定すれば動作する見込み。本番運用前に実カードでのテスト（Stripeテストカード番号を使用）が必要。

## 追記(2026-07-29): ショップの未実装タイプ対応

優先順位2番目の項目に対応。`plane`/`background`/`character`はどちらも今すぐ実装するには前提(地域ロックの再設計、キャラクター/背景アセット)が足りないため、**実装ではなく非表示化**を選んだ。

- `config/shop.php`の`enabled_types`(`potion`/`title`)にプレイヤー向け一覧(`GET /api/shop`)と購入API双方を制限。APIを直接叩かれても422で弾く(UI非表示だけに頼らない)
- `title`タイプは実装した。購入すると`profile_titles`に称号が付与される(ボス称号と同じ仕組みを再利用)
- Owner管理画面側は5タイプとも作成可能なままにしている(将来の準備目的の登録は許容し、プレイヤーに見せる基準だけを分離する設計)
- テスト3件追加(全47件パス)

`plane`(航空券で地域を解放する等)と`background`(レベル別背景と絡める案があるため`docs/AppRoadmap.md`の「レベルごとの背景変化」と合わせて再検討)、`character`(キャラクターアセットが無いと購入の意味がない)は引き続き未着手。

## 追記(2026-07-29): プロフィールの編集・削除

優先順位3番目に対応。

- `PATCH /api/profiles/{profile}`(名前変更)、`DELETE /api/profiles/{profile}`(削除)を追加。どちらも所有者(自分の`UserSchema`配下)以外は403
- 削除時、選択中のプロフィールだったらセッションの`active_profile_id`も解除
- 関連テーブル(`profile_stage_progress`/`profile_titles`/`profile_currency_ledger`/`user_profile_items`/`coin_purchases`)は全てcascadeOnDelete設定済みだったため、削除時のマイグレーション変更は不要
- `profiles`画面に「プロフィールを編集」トグルを追加。編集モードでプロフィールを選ぶと選択ではなく名前変更/削除ができるインライン編集に切り替わる(Netflixのプロフィール管理と同様のUX)
- 副次的に発見: `GET /api/profiles/active`が素の`null`をそのまま返しており、Laravelの仕様(`is_array`/`Arrayable`/`Jsonable`以外はtext/htmlになる)によりアクティブなプロフィールが無い時に**JSONとして不正なレスポンス**を返す既存バグを発見・修正(素の`json_encode`で明示的にJSONを返すよう変更)
- テスト5件追加(全52件パス)
