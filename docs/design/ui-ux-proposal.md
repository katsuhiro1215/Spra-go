# UI/UXデザイン改善提案（ログイン画面 / Ownerダッシュボード）

デザイン担当として、ログイン導線とOwnerダッシュボードのコードを読み、`docs/AppInfo.md` の世界観（ゲームらしさ最優先、老若男女対象）と照らして現状分析と改善提案をまとめる。ローンチまで約1ヶ月という前提で、優先順位も明示する。

## 1. 現状分析

**良い点**

- 認証フロー（`login`/`register`/`owner/login`）はエラーハンドリング（422時のフィールドエラー表示）・ローディング状態が実装済みで、機能としては土台がしっかりしている。
- ダッシュボードの `stages/page.tsx`・`quizzes/page.tsx` は「フィルタ→一覧→Dialogで編集/削除」という同一パターンで統一されており、shadcn/ui（Dialog, Select, AlertDialog, Badge等）を使ったCRUDの型は既にできている。
- 難易度バッジの色分け（初級=緑／中級=amber／上級=rose）など、情報を視覚的に区別する工夫がすでに存在する。
- `profiles/page.tsx` はNetflix風プロフィール選択という設計意図自体はAppInfo.mdの構想通り実装されている。

**課題**

- ログイン・登録・Owner ログインの3画面がほぼ同一コード・同一の無彩色shadcnデフォルトテーマで、見出しも `Login`/`Register` と英語のまま。AppInfo.mdが最重要とする「3Dボタン・アニメーション・演出」がアプリ全体（quiz/play画面含む）に一切見当たらない。ゲームの入口として最初の1画面で世界観が伝わらない。
- Owner/Admin/Userのログイン画面に視覚的な差がゼロ。同じコンポーネントをコピーしただけで、誤って別のログインページに来ても気づけない。
- `profiles/page.tsx` のアバターはイニシャル1文字＋単色四角のみ。「誰でプレイするか選ぶ」ワクワク感が薄く、空状態（プロフィール0件）の導線も弱い。
- ダッシュボードのトップ（`page.tsx`）は見出しのみでKPIがゼロ。Ownerが状況を一目で把握できない。
- サイドナビ（`layout.tsx`）が15項目のフラットリスト（カテゴリー/国/言語/地域/クイズ/ステージ/出題テーマ/ショップ/イベント/コンテンツ/AI生成/システム/Admin/User）。国→地域→ステージ→クイズという強い親子関係があるのに、ナビ上は分断されている。AppInfo.mdの「将来追加」を踏まえると項目はさらに増える前提であり、フラット構造は早晩破綻する。

## 2. ログイン画面の改善提案

- ログイン/登録/プロフィール選択に共通の「世界観ゲート」ビジュアル（背景演出・ロゴ・キャッチコピー）を追加し、最初の1画面からゲームらしさを出す。
- Buttonコンポーネントに3D押下エフェクト（下部に厚みを持たせ、押すと沈む）のバリアントを追加し、既存依存のFramer Motionでプレス/ホバーアニメーションを付与。login/register/quiz系画面へ横展開する。
- Owner/Adminは落ち着いたトーン（管理ツールらしいシンプルな配色）、Userは明るくカラフルなゲーム風トーンに分離し、ラベルも「運営者ログイン」等で明示して誤動線を防ぐ。
- プロフィール選択はイニシャル四角から、動物・キャラクター等のアバターアイコンに変更し、選択時にスケール＋発光などのマイクロインタラクションを追加。0件時は「最初のプレイヤーを作ろう」を強調するCTAにする。
- マイクロコピーを完全に日本語化し、ゲーム風の言い回しに（例：「ログイン」→「ぼうけんへ出発」）。

## 3. ダッシュボードの改善提案

- サイドナビを「コンテンツ管理（国/地域/言語/カテゴリー）」「クイズ運用（クイズ/ステージ/出題テーマ）」「収益・イベント（ショップ/イベント）」「システム（AI生成/システム/Admin/User）」のようにグルーピングし、見出しまたは折りたたみセクションに分割する。
- ダッシュボードトップにKPIカード（登録ユーザー数、直近7日のクリア数、未設定コンテンツ数など）を追加し、Ownerが開くたびに状況を把握できるようにする。
- 国・地域・ステージ・クイズ間の親子関係を、詳細ページのパンくずやタブで可視化し、横断ナビゲーションを容易にする。
- テーブル/フィルタ/フォームの実装パターンを一段階共通コンポーネント化し、今後エンティティが増えても実装コストが線形に増えないようにする。

## 4. 優先順位（Impact / Effort）

**最優先（効果大・工数小、まずここから）**
1. ログイン/登録/プロフィール選択のビジュアルテーマ統一（配色・コピー・ロゴ）
2. サイドナビのグルーピング（折りたたみなしの見出し区切りだけでも十分効果あり）
3. Owner/Admin/Userログインの配色・ラベル差別化

**次点（効果大・工数中）**
4. Buttonの3Dバリアント＋押下アニメーション、プロフィールアバターの強化
5. ダッシュボードトップのKPIカード

**ローンチ後でも可（効果中・工数大）**
6. テーブル/フォームの共通コンポーネント抽象化
7. ダッシュボードの検索・コマンドパレット
8. 「先に体験、後で登録」のオンボーディング再設計

## 5. 参考事例

- **Duolingo**：下部に厚みを持たせ押すと沈む3Dボタン、レッスン直後の紙吹雪演出、「Play first, profile second」のオンボーディング。AppInfo.mdが掲げる「3Dボタン」「正解演出」とまさに同じ設計思想であり、そのまま参考にできる。
- **Notion / Airtable系の管理画面**：サイドバーをラベル付きグループ＋折りたたみで構成し、エンティティが増えても迷わない設計。Owner Dashboardの今後の拡張にそのまま応用できる。
- **Netflixのプロフィール選択**：AppInfo.mdで名指しされている通り、キャラクター性のあるアバターと選択時のフォーカスアニメーションが「誰が遊ぶか選ぶ」ワクワク感を生んでいる。現状の`profiles/page.tsx`はレイアウトのみを模倣しており、ビジュアルの作り込みが追いついていない。
