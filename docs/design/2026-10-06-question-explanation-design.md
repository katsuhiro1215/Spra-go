# 問題の「解説」— 設計書

- 作成日: 2026-10-06
- ステータス: 案（Ownerの承認済みの大枠を、書きおろしたもの）。Owner合意済み（2026-10-06のやりとり）: 問題ごとに、答えたあとに見られる解説（要約・例文・使いどころ・似た語）を持たせる。英語も都道府県クイズも、同じ入れものを使う。進め方は、段階1（仕組み＋都道府県クイズ）→ 段階2（英語のあいさつ）→ 段階3（ほかの問題をじわじわ）
- 前提: 答えのカード（`docs/design/2026-10-05-flag-quiz-design.md` 7-2 など）、自動ふりがな（`frontend/src/components/app/auto-furigana.tsx`）、都道府県クイズ（`docs/design/2026-10-05-prefecture-quiz-design.md`）
- 対応するタスク: `TASKS.md` 問題の解説

## 1. 目的

クイズに答えたあと、「なぜそうなのか」「どんなときに使うのか」まで分かるようにして、ただの○×で終わらせず、学びを残す。

**うまくいった目安**

1. 答えたあとのカードに、その問題の短い解説（要約）が出る。正解でも不正解でも出る
2. 解説に例文・使いどころ・似た語があるときは、「くわしく見る」で開ける
3. 解説のない問題は、今のまま（何も変わらない）
4. 解説は、答える前には、画面にも通信にも出ない（正解の手がかりにならない）
5. 都道府県クイズは、全問に要約が付く。難読地名は、読みと、その地名の説明が付く

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 入れもの | `questions.explanation`（JSON、空でよい）。問題ごとに1つ。言葉の表は作らない（英語の問題には、言葉の表がなく、`meta` も空のため） |
| 項目 | `summary`（1〜2文）・`example`（例文と日本語訳）・`usage`（使いどころ）・`related`（似た語・似た言い方と、ひとこと）。**すべて任意** |
| 画面 | 答えのカードに `summary` を出す（正解・不正解とも）。例文などがあれば「くわしく見る」で開く。ふりがなは、今の自動ふりがなを使う。英語の例文は、そのまま出す |
| 隠し方 | 問題の取得（ステージ・おさらい・ほか）には、出さない。答えのAPIの返事にだけ、入れる |
| 空の問題 | 今のまま（解説の欄を出さない） |
| 内容の入れ方 | 都道府県クイズ: 県庁所在地・地方・となり・名物などの要約は、県のデータ表から自動で作る。難読地名の説明は、データ表の `hard` に `note` を足す。英語: あとの段階で、取り込みの表に列を足す |
| 段階 | 段階1＝仕組み＋都道府県クイズ。段階2＝英語の基本のあいさつ100選。段階3＝名物・名所・お祭りの説明など、ほかの問題をじわじわ |

## 3. データ

### 3-1. 列

- `questions` に `explanation`（`json`・`nullable`）を足すマイグレーション（追加のみ）
- `Question` モデル: `fillable` に足し、`array` にキャスト。**`$hidden` に入れる**（問題を返すすべての口で、自動的に隠れる。答えのAPIだけが、属性を直接読んで返す）

### 3-2. 形

```json
{
  "summary": "『室蘭』は、『むろらん』と読むよ。北海道の南にある、港のまちだよ。",
  "example": { "text": "Thank you very much.", "translation": "どうもありがとうございます。" },
  "usage": "お礼を言うとき。友だちにも、先生にも使えるよ。",
  "related": [{ "term": "Thanks.", "note": "くだけた言い方" }]
}
```

- `QuestionExplanation::normalize(mixed): ?array`（新設）が、書くときにそろえる: 知らないキーは捨てる・文字は前後の空白を取る・空の項目は捨てる・`related` は `term` のあるものだけ・なにも残らなければ `null`
- 書く口（`FlagQuizWriter`・のちの取り込み）は、必ずこれを通す

## 4. 答えのAPI

- `POST /api/questions/{id}/answer` の返事に `explanation`（なければ `null`）を足す。練習（やり直し）の返事にも足す
- HPが足りない（409）の返事には入れない（答えていないため）
- 問題の取得（`PlayableQuestion` を通る口すべて）は、`$hidden` のため `explanation` を含まない

## 5. 画面

- 部品 `AnswerExplanation`（新設、`frontend/src/components/quiz/answer-explanation.tsx`）: `summary` を出し、`example`・`usage`・`related` のどれかがあれば「くわしく見る ▼」を出す。開くと、例文（と日本語訳）・使いどころ・似た語を出す。問題が変わったら、閉じた状態に戻す（`key` で作り直す）
- `quiz-session.tsx`: 答えのAPIの返事の `explanation` を持ち、答えのカードの「こたえは…」の下に出す。難読地名の問題は、`meta.plain` の語にふりがなを付けない（答えの読みは、解説の文の中に、ひらがなで書いてある）
- スマホの幅（375px）で、カードが画面からはみ出さない（今のカードの縦スクロールを使う）

## 6. 都道府県クイズの内容（段階1）

県のデータ表から、問題を作るときに、同じところで解説も作る（`PrefectureQuizPlanner`）。

| 問いの形 | 要約 |
|---|---|
| 名物（`foods`）| 「{名物}は、{県}の名物だよ。」 |
| 名所（`sights`）| 「{名所}は、{県}にあるよ。」 |
| お祭りなど（`culture`）| 「{もの}は、{県}で有名だよ。」 |
| 県庁所在地・その逆 | 「{県}の県庁所在地は{市}だよ。」。県の名前と市の名前がちがうときは、「{県}と名前がちがうから、まちがえないでね。」を足す |
| 何地方か | 「{県}は、{地方}地方にあるよ。」 |
| となりの県 | 「{県}は、{となりの県…}と、県ざかいが接しているよ。」（データ表のとなりを、すべて並べる） |
| はめ込み（県庁所在地） | 「こたえは、{市}は{県}、…だよ。」 |
| 難読地名 | 「『{漢字}』は、『{読み}』と読むよ。{note}」 |

- `database/data/prefectures.php` の `hard` の各項目に `note`（その地名の説明。1〜2文）を足す。141語ぶん。**Ownerの確認が要る内容**（私が書き、公開前にOwnerが確認する）。`note` がなければ、読みの文だけ
- 説明に出る漢字は、辞書で読めること（足りない語は `tools/furigana/prefecture-explanation-words.json` に足す）。難読地名の漢字は、辞書に入れない（今のテストが守る）
- 名物・名所・お祭りの「ひとこと説明」（例: 広島風お好み焼き）は、段階3で、データ表に足す

## 7. テスト

- **サーバー（Pest）**: `QuestionExplanation::normalize`（そろえ方・空は null）、書き込み（解説が書かれる・解説なしの問題は null・二重実行で増えず直る）、答えのAPI（解説が返る・解説なしは null・練習でも返る）、問題の取得（`explanation` が出ない。ステージの出題とおさらいの両方）、都道府県の計画（全問に要約がある・形ごとの文・難読地名は読みと `note`・同じ表から同じ計画）、データ表（難読地名141語すべてに `note`）、ふりがな（解説の文の漢字が、辞書で読める）
- **画面（Vitest）**: 出すものがあるかの判定、`AnswerExplanation` の開く前の見え方（要約が出る・詳細がなければボタンなし・あれば「くわしく見る」・空なら何も出さない・`plain` の語にふりがなを付けない）。開いたときの見え方は、ブラウザで確かめる（Vitest はブラウザの代わりを使わない）
- **ブラウザ**: 都道府県クイズで、正解・不正解のどちらでも要約が出る。難読地名で読みと説明が出る。スマホ幅で見え方を確かめる。確認のあと、開発用のデータを元に戻す

## 8. やらないこと（段階1）

- 英語の解説（段階2）、名物などの個別の説明（段階3）
- Ownerの管理画面での解説の編集
- 解説の読み上げ、覚え方のコツ（要望があれば、あとで項目を足す。形がJSONなので、足しやすい）
- 解説を見たかどうかの記録
