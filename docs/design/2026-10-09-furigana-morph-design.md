# ふりがなの辞書を、形態素解析で作る — 設計書

- 作成日: 2026-10-09
- ステータス: 実装済み（2026-10-09。Ownerの了承 2026-10-09: 形態素解析で読みを一括で作る方向）
- 前提: 自動ふりがな（`frontend/src/components/app/auto-furigana.tsx`・`frontend/src/lib/furigana-dictionary.json`）。辞書は約1,400語を手で足したもの

## 1. 目的
問題・選択肢・解説の漢字に、正しいふりがなが付くようにする。

**今の問題**（2026-10-09の点検。英語の問題の文 約3.6万件）
1. 辞書にない漢字が約1,600種類（的・要・好・疲・彼女・解決・計画 …）で、ふりがなが付かない
2. 1文字の読みで誤る（「表す」→ひょうす、「入る」→いる、「面白い」→「面しろい」、「会った」→かいった、「大きい」→だいきい）
3. 手で足し続けても、問題が増えるたびに穴が出る

**うまくいった目安**
1. 英語の問題の文で、辞書にない漢字が、人名・特殊な語を除いて、ほぼなくなる
2. 点検で見つけた誤読（上の例）が、手で足さなくても、正しく付く
3. 画面を表示する仕組み（`AutoFurigana`）は、同じ使い方のまま。表示の速さが落ちない

## 2. 決定事項
| 項目 | 決定 |
|---|---|
| 方式 | 形態素解析（Sudachi。Apache 2.0）で、問題の文から「語 → 読み」の辞書を**作っておく**（作るときだけ使う。サーバー・画面には入れない） |
| 辞書 | 手で直した辞書（`furigana-dictionary.json`）は、そのまま**優先**。作った辞書（`furigana-generated.json`）は、足りない語を補う。同じ語は手の辞書が勝つ |
| 語の単位 | Sudachiの短い単位（A）。活用する語は、送りがなまで含めて1語（例: 表す→あらわす、大きい→おおきい）。今の辞書と同じ形 |
| 読みが複数ある語 | 文脈で変わる語（上: うえ／じょう など）は、いちばん多い読みを採る。複数の読みが出た語は、点検用の一覧に書き出して、必要なものは手の辞書で直す |
| 材料 | 問題の文・選択肢・解説・単語帳の意味や例文・国の紹介文（DBの文字を、`furigana:corpus` で書き出す） |
| 数字の後ろ | 今までどおり（日・人・月は専用の読み。`counter-reading.ts`）。辞書より先に見る |
| 表示の速さ | 辞書が大きくなるので、最初の1文字で引ける索引を付ける（今は全語を順に調べている） |

## 3. 設計
### 3-1. 材料を書き出す（Laravel）
`php artisan furigana:corpus {path}`: 次の文字を、重複を除いて1行ずつ書き出す（改行は空白に）。
- `questions.prompt`、`question_choices.label`、`questions.explanation`（JSONの文字の値）
- `words.meanings`・`usage`・`examples`（JSONの文字の値）、`countries.name`・`intro_message`
- 漢字を含む行だけ

### 3-2. 辞書を作る（`tools/furigana/build_generated.py`）
- 入力: 材料のファイル。出力: `frontend/src/lib/furigana-generated.json`（語→ひらがなの読み。長い語が先）、`tools/furigana/conflicts.txt`（読みが複数出た語と回数）
- 作る語: 漢字を含む語（Sudachiの1単位）。ひらがな・カタカナ・英数字だけの語は作らない。読みはカタカナ→ひらがなに直す
- 数字の語（10月・3日 など）は作らない（`counter-reading.ts` が読む）
- 材料に出た回数が少なすぎる（1回）語も入れる（辞書は大きくなるが、穴をなくすことを優先する）
- 前提のソフト: `pip install sudachipy sudachidict_core`（作るときだけ。`tools/furigana/README.md` に書く）

### 3-3. 画面側（`auto-furigana.tsx`）
- 辞書 = 作った辞書に、手の辞書を上書きしたもの。最初の1文字ごとに、長い語が先の一覧を作る（索引）
- そのほかの動き（plain・readings・数字の後ろ）は変えない

## 4. テスト
- Laravel: `furigana:corpus` が、材料を書き出す（重複なし・漢字のない行は出ない）
- Vitest: 作った辞書の語が使われる（的・解決 など）／手の辞書が同じ語で勝つ／最長一致／索引を使っても今までのテストが通る
- 確認: 英語の問題の文を点検し直し、辞書にない漢字の数と、1文字の誤読を数え直す。実際の画面（英語のクイズ・単語帳）をふりがなONで見る

## 5. やらないこと
- 文ごとに読みを保存して配る方式（文脈で読みが変わる語は、いちばん多い読みで妥協する。誤読は一覧から手で直す）
- 辞書を画面ごとに分けて、あとから読み込む仕組み（大きさが問題になってから）
- ふりがなを漢字の部分だけに付ける（送りがなには付けない）表示の変更（今の形を保つ）

## 6. 実装の順序
1. `furigana:corpus`（テスト付き）
2. 作成ツールと、最初の辞書
3. 画面側（索引・辞書の合わせ方）とテスト
4. 点検・画面の確認、SPEC・TASKS
