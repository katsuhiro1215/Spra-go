# ワールド画面（自分の町）＋ポイントで買って置く — 設計書

- 作成日: 2026-09-26
- ステータス: Owner合意済み（設計の各区切りを対話で確認）
- 参考モックアップ: https://claude.ai/artifact/JJNrVbfAxEz1q7h6Tadbw9 （使い捨て。リポジトリには含めない）

## 1. 背景と目的

問題（コンテンツ）は揃ってきたが、ゲームとしての面白さが足りないという課題がある。Ownerの構想により、コンセプトを次のように転換する。

> 言葉を学ぶことで、世界を旅できるようになる（学ぶほど世界が広がる）

学習 → ポイント獲得 → アイテム購入 → 自分の町に配置 → レベルアップ → 新しい土地・国の解放、というループを持つ生活シミュレーション型の体験にする。SPEC.mdの「クイズ＝戦闘のRPG」からの大きな仕様変更にあたる（Owner承認済み）。

### 全体の分割

大きすぎるため、次の4つのサブプロジェクトに分け、それぞれ設計書 → 実装計画 → 開発の順で進める。本書は①の設計書である。

1. **ワールド画面＋ポイントで買って置く**（本書）
2. レベルによる土地の解放と、新しい国への旅（演出含む）
3. 復習を混ぜた出題（「今日のレッスン」）
4. （①に統合）ワールドを中心にしたホーム画面の作り直し

## 2. 決定事項（Owner確認済み）

| 論点 | 決定 |
|---|---|
| 描画方式 | SVG＋Reactで描く（モックと同じ方式）。規模が大きくなり重くなったらPixiJSを検討 |
| 通貨 | **学習ポイントを新設**。正解・ステージクリアでしか貯まらない。課金できる既存コインはHP回復などの便利アイテム用に残す |
| 配置 | **マス目に自由配置**。空きマスならどこでも置け、移動・バッグに戻すもできる。1マスのアイテムのみ |
| 画面構成 | **ワールドをホームにし、ナビを5タブ（学ぶ／旅する／ショップ／バッグ／世界）に刷新** |

## 3. 範囲

### やること
- ログイン後のホーム（`/`）を町の画面にし、ナビを5タブにする
- 学習ポイントの新設（貯まる・使う・台帳に記録）
- 町に置くアイテムの品ぞろえ（必要レベルつき）と購入
- 町のマス目へ自由に置く・動かす・バッグに戻す
- Spruが町にいて、購入・配置で喜ぶ

### やらないこと（後のサブプロジェクト・別タスク）
- レベルで土地が広がる／新しい国へ旅する演出、モックにあった雲に隠れた竹林・インドネシアの島・「旅のじゅんび」リスト（②）
- 復習を混ぜた「今日のレッスン」（③）
- アイテムの回転、複数マスにまたがる建物
- アイテムの売却（返金）
- Blender製素材への差し替え（マスコット部の進み具合しだい）
- 町以外の画面の見た目を新しい配色にそろえる作業（別タスクとしてTASKS.mdに積む）
- フロントエンドのテストフレームワーク導入

## 4. ゲームのルール

- **ポイントの獲得**: 正解で+10、ステージクリアで+50。既存コインの獲得ルールは変えない
- **最初の100pt**: 町の画面を初めて開いたとき、全プロフィール（既存ユーザー含む）に1回だけ100ptを渡す
- **学習レベル**: 既存のXPによるレベル（`intdiv(xp,100)+1`、10問正解で1レベル）をそのまま使う
- **アイテム**: 値段（ポイント）と必要レベルを別々に持つ。「ポイント不足」と「レベル不足」を区別して表示する
- **土地**: 7×7マスで固定。Spruの家・道・鳥居・灯籠は最初からある動かせない「目印」で、全体の約4分の1を占める
- **配置**: 同じアイテムを何個でも買える（置ける数は空きマスで決まる）。置いたものはいつでも移動・バッグに戻せる。売却はしない
- **購入したアイテムはバッグに入る**。画面はそのまま「置く場所を選ぶ」状態に切り替えるため、体験上は買ってすぐ置ける。途中でやめてもバッグに残る。町が埋まっていても購入できる
- **「つづきから学ぶ」ボタン**: ③ができるまでの代わり。最後に遊んだステージが未クリアならそのステージ、クリア済みなら同じ国・カテゴリー・難易度の次のステージへ。行き先が無ければ `/learn` へ

報酬額・初回付与額・土地の広さは `config/world.php` に定数として置く。

## 5. データ設計

追加のみで既存データは変更・削除しない。適用は通常の `php artisan migrate`（`migrate:fresh` は使わない）。

### 5-1. `user_profiles` に列を追加

| 列 | 型 | 説明 |
|---|---|---|
| `points` | unsigned int, default 0 | 学習ポイント残高 |
| `world_welcomed_at` | timestamp, nullable | 初回100ptを渡した日時（二重付与防止） |

- 増減は既存の `UserProfile::applyEconomy()` に種類 `point` を追加して行う（0未満にしない）。台帳 `profile_currency_ledger` に `type = point` で記録する（`type` 列は文字列のためスキーマ変更不要）
- 台帳の理由（`reason`）: `answer_correct`（既存）、`stage_clear`（既存）、`world_welcome`（新規）、`shop_purchase`（既存）

### 5-2. `shop_items` を拡張（品ぞろえ）

| 変更 | 内容 |
|---|---|
| 種類 `decoration` を追加 | 町に置くアイテム。`config/shop.php` の `enabled_types` と、Owner管理画面のショップ編集で選べる種類に追加 |
| 列 `currency` | string, default `coin`。`coin` / `point`。既存の回復薬・称号は `coin` のまま |
| 列 `min_level` | unsigned small int, default 1。必要レベル |
| `meta.asset_key` | 絵の指定（例: `bench`）。既存の `meta` JSON列を使う |

初期の品ぞろえ（8種類前後）はシーダーで投入する。必要レベルはLv.1〜12程度に散らす（例: ベンチ・花だん・ちょうちんはLv.1、桜の木・自転車は中盤、屋台は後半）。具体的な値段・レベルは実装計画で確定する。

### 5-3. 新テーブル `profile_world_items`（持っているアイテム）

| 列 | 型 | 説明 |
|---|---|---|
| `id` | bigint | |
| `user_profile_id` | FK → user_profiles（削除時カスケード） | 持ち主 |
| `shop_item_id` | FK → shop_items | どのアイテムか |
| `x` / `y` | unsigned tinyint, nullable | 置いた位置。両方nullならバッグの中 |
| timestamps | | |

- 一意制約: (`user_profile_id`, `x`, `y`)。同じマスに2つ置けないことをDBで保証する（MySQLの一意制約はNULLを重複扱いしないため、バッグの中身には影響しない）
- 購入履歴は既存の `user_profile_items` にもこれまで通り記録する

### 5-4. 土地の設定 `config/world.php`

- 広さ（7）、目印（Spruの家・鳥居・灯籠）の位置、道のマスの一覧を持つ
- 目印と道のマスは配置不可
- 全員同じ町のためDBには持たない。②で土地が広がる際にこの設定を拡張する

## 6. API仕様

既存の書き方（`routes/api.php`、`auth:sanctum`、操作対象はセッションの `active_profile_id` のプロフィール）に合わせる。

### 6-1. 新規

**`GET /api/world`** — 町の画面を開いたときに呼ぶ

```json
{
  "land": {
    "size": 7,
    "landmarks": [{ "key": "spru_house", "x": 1, "y": 1 }],
    "paths": [[2, 0], [2, 1]],
    "blocked": [[1, 1], [2, 0], [2, 1]]
  },
  "items": [{ "id": 1, "shop_item_id": 3, "name": "ベンチ", "asset_key": "bench", "x": 2, "y": 4 }],
  "bag": [{ "id": 2, "shop_item_id": 5, "name": "ちょうちん", "asset_key": "lantern" }],
  "profile": { "id": 1, "points": 120, "level": 3, "xp": 270, "hp": 18, "max_hp": 20, "coins": 300 },
  "welcome_available": true,
  "continue_stage_id": 42
}
```

- `blocked` は目印と道のマスの和集合
- `continue_stage_id`: 最後に遊んだステージ（`profile_stage_progress` の更新日時が最新のもの）が未クリアならそのID、クリア済みなら同じ `category_id`・`country_id`・`difficulty` で `stage_number` が次のステージのID。無ければ `null`

**`POST /api/world/welcome`** — 最初の100ptを受け取る

- `world_welcomed_at` がnullなら100ptを付与して日時を記録。受け取り済みなら何もしない
- レスポンス: `{ "granted": true|false, "points": 220 }`
- 付与はトランザクション内でプロフィール行をロックして行う

**`PATCH /api/world/items/{profileWorldItem}`** — 置く・動かす・バッグに戻す

- リクエスト: `{ "x": 3, "y": 4 }`、バッグに戻すときは `{ "x": null, "y": null }`（片方だけnullは不可）
- チェックとエラー（422、メッセージは日本語）:
  - 自分のプロフィールのアイテムでない → 404
  - 土地の範囲外 → 「土地の外には置けません」
  - 目印・道のマス → 「そこには置けません」
  - 他のアイテムと重なる → 「そこにはもう置いてあります」（同時操作による重なりも一意制約違反を捕まえて同じエラーにする）
- レスポンス: 更新後のアイテム（`GET /api/world` の `items` と同じ形）

### 6-2. 既存の拡張

**`GET /api/shop`**
- `decoration` も返す。各アイテムに `currency`・`min_level`・`asset_key`・`locked`（今のプロフィールのレベルが必要レベル未満なら true）を付ける。アクティブプロフィールが無い場合はレベル1として判定する
- 既存の回復薬・称号の返し方は変えない（フィールドが増えるだけ）

**`POST /api/shop/{shopItem}/purchase`**
- `currency = point` のアイテム:
  - レベル不足 → 422「レベルが足りません」
  - ポイント不足 → 422「ポイントが足りません」
  - ポイントを引き、`profile_world_items` にバッグの中身として1行作る
  - レスポンスに `world_item`（`bag` と同じ形）を含める
- 購入処理全体をトランザクションで囲み、プロフィール行をロックする（残高の二重引き落とし防止。既存のコイン払いにも同じ対策が無いため、あわせて直す）
- レスポンスの `profile` に `points` を含める

**回答API（`POST /api/questions/{question}/answer`）とステージクリア処理**
- 正解時の `applyEconomy` に `point +10`、ステージクリア時に `point +50` を追加
- レスポンスの `profile` に `points` を含める

**プロフィール情報を返すAPI（`/api/profiles/active` など）**
- `points` を含める（ヘッダーのポイント表示に使う）

### 6-3. 作らないもの
- 売却（アイテム削除）のAPI

## 7. 画面設計

### 7-1. 画面の割り当て（5タブ）

| タブ | パス | 内容 |
|---|---|---|
| 世界 | `/` | ログイン後のホームを町の画面にする。未ログイン時のLPは現状維持 |
| 学ぶ | `/learn` | 今のホームの中身（国選択・世界地図・ミニアプリ）をそのまま移す |
| 旅する | `/passport` | 当面はパスポートを表示。②で旅のハブに作り替える |
| ショップ | `/shop` | 「町のアイテム（ポイント）」と「べんりアイテム（コイン: 回復薬・称号）」の2段に分ける。町のアイテムを買うと `/?place={worldItemId}` に移動し、置く場所を選ぶ状態になる |
| バッグ | `/bag`（新規） | まだ置いていないアイテムの一覧。「置く」で `/?place={worldItemId}` へ |

### 7-2. 町の画面の部品（`frontend/src/components/world/`）

| 部品 | 役割 |
|---|---|
| `iso.ts` | マス目 ↔ 画面座標の計算だけを持つ純粋関数 |
| `WorldScene` | 地面・道・目印・アイテムをSVGで描画。奥から手前の順（x+y）に重ねる |
| `ItemArt` | `asset_key` から絵を引く窓口。今はSVG部品、後でBlender画像に差し替える際はここだけ直す |
| `Spru` | 待機・喜ぶの2パターンと吹き出し |
| `WorldHud` | 上部のポイント・HP・レベル・XPバー。次に買えるようになるアイテム（例:「Lv.5で屋台」）も表示 |
| `PlacementBar` | 「〇〇を置く場所をタップ」の案内と「やめる」 |
| `ItemActionSheet` | 置いたアイテムをタップすると出る「動かす／バッグにしまう」 |
| `WelcomeGift` | 最初の100ptプレゼント（Spruが「旅のおこづかいだよ」と渡す演出） |
| `BottomNav` | 既存ファイルを5タブ・線画アイコンに作り替える |
| 「つづきから学ぶ」ボタン | `continue_stage_id` があれば `/quiz/{id}`、無ければ `/learn` へ |

### 7-3. 操作の流れ
- **置く**: 置けるマスだけ光る → タップ → 画面を先に反映し、APIが失敗したら元に戻してエラー理由を表示 → Spruが喜ぶ
- **動かす・しまう**: 置いたアイテムをタップ → シートから選ぶ → 「動かす」なら置く場所を選ぶ状態へ

### 7-4. 見た目・その他
- モックの明るい昼の配色。スマホ縦画面が基本、PCでは中央に幅480px程度で表示
- マス・アイテムは本物の `<button>` にし、読み上げ用のラベルを付ける
- 既存のふりがな・文字サイズ・効果音・動きを減らす設定（`prefers-reduced-motion`）に合わせる
- Spruは設定画から切り抜いた仮画像（`frontend/public/spru/`）を使い、Spru Masterができたら差し替える。仮素材の使用はマスコット部の資料にも記録する

## 8. テスト

### 8-1. バックエンド（Pest、テストを先に書いてから実装）
- ポイント: 正解で+10、ステージクリアで+50が付き、台帳に記録される
- 初回付与: 1回目で100pt付与／2回目は何も起きない
- ショップ一覧: `decoration` が `currency`・`min_level`・`asset_key`・`locked` つきで返る
- 購入: ポイントが減りバッグに入る／ポイント不足・レベル不足はエラー／既存のコイン払い（回復薬・称号）の挙動は変わらない
- 配置: 空きマスに置ける／範囲外・目印・道・重なりはエラー／他人のアイテムは操作できない／移動・バッグに戻すができる
- 町の情報: レスポンスの形、`continue_stage_id` の3パターン（未クリア→同じ／クリア済み→次／記録なし→null）

### 8-2. フロントエンド（ブラウザで実操作確認、Playwright）
- 100ptを受け取る → 買う → 置く → 動かす → しまう → バッグから置き直す
- 「レベル不足」「ポイント不足」の表示
- 5タブの行き来、`/learn` が今のホームと同じように動く、未ログインのLPが変わっていない
- スマホ幅（390px）とPC幅の両方
