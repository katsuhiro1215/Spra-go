## 1. 背景と目的

今は、1つのステージの問題は決まっていて（クイズは10問、英語は6問など）、順番だけが変わる。くり返しは次の3つだけ。

- 結果の画面の「まちがえた問題だけもう一度」（練習なので記録しない）
- 「もう一度」（ステージを全部やり直す）
- 相棒の「復習」（まちがえたままの問題を1日5問、1日1回。`app/Support/Review.php`）

正解した問題が、日をあけてまた出ることはない。新しい問題はステージごとにまとめて出る。

Ownerの要望は、モチたんのように「同じ問題をくり返し出しながら、少しずつ新しい問題が出る」形。覚えられるようにすることと、問題を作る負担を減らして今の約1,470問を長く使うことが目的。

**うまくいった目安**

1. まちがえた問題や覚えかけの問題が、忘れかけたころにまた出る
2. 新しい問題は、一度にたくさんではなく少しずつ出る
3. ステージを進める楽しさ（クリア・ボス・チケット）は壊さない
4. 毎日少し遊ぶだけで、自然に復習できる

## 2. 決定事項（Owner確認済み）

| 項目 | 決定 |
|---|---|
| 出す場所 | ステージと毎日の復習の両方 |
| ステージへの混ぜ方 | ボス以外のステージに、前の問題を最大2問足す（10問→12問）。ボスには混ぜない |
| 間隔 | 1日後→3日後→1週間後→2週間後→1か月後（5段階） |
| 毎日の復習の量 | 1日1回・10問まで（今は5問） |
| 覚え具合の持ち方 | 問題ごとの覚え具合を新しい表に持つ。今までの答えの記録から最初の値を作る |
| パスポート | 「覚えた問題 ○問」を出す |

## 3. 覚え具合のルール

### 3-1. 段階と次に出る日

プレイヤーと問題の組ごとに、覚え具合を1行で持つ（4-1）。

| 段階 | 次に出るまでの間 |
|---|---|
| 1 | 1日 |
| 2 | 3日 |
| 3 | 7日（1週間） |
| 4 | 14日（2週間） |
| 5 | 30日（1か月） |
| 覚えた | もう出さない |

### 3-2. 答えたときの動き

| できごと | 段階 | 次に出る日 |
|---|---|---|
| 初めて答えた（正解でも不正解でも） | 1 | 次の日 |
| 出す日（その日かそれより後）に正解 | 1つ上がる（2→3→4→5） | その段階の間だけ先 |
| 段階5で出す日に正解 | 覚えた | なし |
| まちがえた（いつでも。覚えた問題でも） | 1に戻る（覚えたも取り消す） | 次の日 |
| 出す日より前に正解（「もう一度」などで） | 変わらない | 変わらない |
| 覚えた問題に正解 | 変わらない | なし |

- 最後から2つ目の行は、同じステージを何度も遊んで段階を上げてしまうのを防ぐため
- 「覚えた」になるのは、最初に答えたあと、日をあけた5回の復習で続けて正解したとき
- 初めて正解した問題も段階1にするのは、次の日にもう一度出して、たまたまの正解でないかを確かめるため

### 3-3. 記録しない答え

- 結果の画面の「まちがえた問題だけもう一度」（練習、`practice`）は、今までどおり何も記録しない
- 体力が0で答えられなかったとき（`blocked`）も記録しない
- プロフィールを選んでいない答え（未ログインの国のミニクイズなど）も記録しない

### 3-4. 日付

- 「その日」は町の水やりなどと同じく、日本時間の日付（`Garden::today()`）
- 次に出る日は「その日＋間の日数」の日付で持つ（時刻は見ない）

### 3-5. 今までの記録からの引き継ぎ

- 今までの答えの記録（`profile_currency_ledger` の `answer_correct`・`answer_wrong`、`question_id` があるもの）を、プロフィールごとに古い順に3-2のルールで読み直して、覚え具合の表の最初の値を作る
- 答えた日は、記録の時刻を日本時間の日付にしたもの
- 消された問題の記録は読み飛ばす
- 1回だけ流すマイグレーションで行う（開発用のデータの町テストなども引き継がれる）

## 4. データ・設定・サーバー

### 4-1. 表 `profile_question_memories`（新規）

| 列 | 型 | 説明 |
|---|---|---|
| `id` | bigint | |
| `user_profile_id` | FK | プロフィールが消えたら消える（cascade） |
| `question_id` | FK | 問題が消えたら消える（cascade） |
| `level` | tinyint | 段階（1〜5） |
| `due_on` | date null | 次に出る日。覚えたら null |
| `mastered_on` | date null | 覚えた日。まちがえたら null に戻す（ほかの列と同じく日付で持つ。今までの記録からの引き継ぎでも日付しかわからないため） |
| `last_answered_on` | date | 最後に答えた日 |
| `created_at`・`updated_at` | | |

- `user_profile_id` と `question_id` の組は一意
- 出す問題を探すため、`user_profile_id`・`due_on` に索引を付ける

### 4-2. 設定（`config/review.php`、新規）

```php
return [
    'intervals' => [1 => 1, 2 => 3, 3 => 7, 4 => 14, 5 => 30], // 段階 → 次に出るまでの日数
    'daily_size' => 10, // 毎日の復習の最大の問題数
    'stage_mix' => 2,   // ボス以外のステージに足す最大の問題数
];
```

今の `config/companions.php` の `review_size`（5）は使わなくなるので消す。

### 4-3. 覚え具合の計算（`app/Support/QuestionMemory.php`、新規）

- `record(UserProfile $profile, int $questionId, bool $correct, ?string $today = null): void` — 3-2のルールで1行を作る・直す。`$today` を省くと `Garden::today()`（引き継ぎのマイグレーションでは記録の日付を渡す）
- `dueQuery(UserProfile $profile)` — 出す日が来た問題（`due_on <= 今日`、覚えていない、鍵の国の問題でない）の問い合わせ。鍵の国は `Travel::lockedCountryIds($profile)`。国のない問題は鍵にならない
- `dueIds(UserProfile $profile, int $limit, array $excludeIds = [], ?int $preferCountryId = null): list<int>` — 出す日が来た問題を、`$preferCountryId` の国の問題を先に、そのあと出す日が古い順（同じなら記録の古い順）に最大 `$limit` 個返す
- `masteredCount(UserProfile $profile): int` — 覚えた問題の数
- `rebuildFromLedger(): void` — 3-5の引き継ぎ（マイグレーションから呼ぶ）

### 4-4. 答えのAPI（`POST /api/questions/{question}/answer`）

- 記録する答え（3-3の記録しない答え以外）で、ごほうびを付けたあとに `QuestionMemory::record($profile, $question->id, $isCorrect)` を呼ぶ

### 4-5. ステージを遊ぶAPI（`GET /api/stages/{stage}`）

- ボス以外で、プロフィールを選んでいるときだけ、`QuestionMemory::dueIds($profile, config('review.stage_mix'), このステージの問題のid, $stage->country_id)` の問題を足す
- 各問題に `review`（足した問題は true、ステージの問題は false）を付ける
- ステージの問題と足した問題を混ぜて、ばらばらの順にする
- 出す日が来た問題がなければ足さない

### 4-6. ステージのクリアのAPI（`POST /api/stages/{stage}/complete`）

- `score` はステージの問題だけの正解数（画面が送る。5-1）
- 念のため、サーバーでも `score` をステージの問題の数までに抑える（最高点がステージの問題の数を超えないように）

### 4-7. 毎日の復習（`app/Support/Review.php`・`/api/review`）

- `Review::questionIds($profile, $limit)` を `QuestionMemory::dueIds($profile, $limit)` に置き換える（答えの記録から「まちがえたまま」を探すやり方をやめる）
- 出す数は `config('review.daily_size')`（10）
- 1日1回・やりきると相棒のなかよし度が増える・出せる問題がないと始められない、は今のまま

### 4-8. パスポート（`GET /api/passport`）

- `mastered_count`（覚えた問題の数）を足す。プロフィールを選んでいなければ 0

## 5. 画面

### 5-1. クイズ（`components/quiz/quiz-session.tsx`）

- 問題の型（`components/quiz/types.ts` の `QuizQuestion`）に `review?: boolean` を足す
- `review` が true の問題は、問題番号の横に「おさらい」の小さな札を付ける
- 最後に送る点数（`onFinish(score)`）は、`review` でない問題の正解だけを数える。どの問題が点数に入るかは関数 `countsTowardScore(question)` にまとめる
- 全問正解の音は、今と同じく出した問題ぜんぶに正解したときに鳴らす
- 相棒の復習の問題には `review` が付かないので、札は出ない（復習そのものが、おさらいのため）

### 5-2. 文言

| 場所 | 今 | これから |
|---|---|---|
| 町の相棒の復習のひとこと（`components/world/companions.ts`） | この前まちがえた問題、いっしょにやってみよう！（N問） | おさらいの問題、いっしょにやってみよう！（N問） |
| おつかいの「復習」（`components/world/errands.ts`） | この前まちがえた問題、復習してみよう | おさらいの問題を解いてみよう |

結果の画面の「まちがえた○問に もう一度チャレンジ」は、その回の練習のことなので変えない。

### 5-3. パスポート（`/passport`）

- 上の札の並び（スタンプ・旅した国）に「覚えた問題 N」を足す

## 6. テスト

### 6-1. サーバー（Pest）

- 覚え具合のルール（`QuestionMemory::record`）: 初めての正解・不正解は段階1で次の日／出す日に正解で1つ上がり、間が3・7・14・30日／段階5で正解すると覚えた／まちがえると1に戻り覚えたも取り消す／出す日より前の正解と覚えた問題の正解は変わらない
- 出す問題（`dueIds`）: 出す日が来た物だけ／覚えた物・鍵の国の物・除く物は出ない／指定した国が先・そのあと出す日が古い順／数の上限
- 答えのAPI: 記録する答えで表が変わる。練習（`practice`）・体力0（`blocked`）では変わらない
- ステージを遊ぶAPI: ボス以外に出す日が来た問題が最大2問足され `review` が付く／ボスには足さない／ステージ自身の問題は足さない／出す日が来た問題がなければ足さない
- ステージのクリアのAPI: `score` がステージの問題の数を超えても、最高点は問題の数まで
- 毎日の復習: 出す日が来た問題（正解したことのある問題も）が古い順に最大10問／消された問題は出ない（今のテストを直す）
- 引き継ぎ: 今までの記録を古い順に読み直した結果になる（まちがえた→正解→…の順と日付で段階が決まる）
- パスポート: `mastered_count`

### 6-2. 画面（Vitest）

- `countsTowardScore`: `review` の問題は数えない
- 文言（`companions.ts`・`errands.ts` のテストを直す）

### 6-3. ブラウザでの確認

- ボス以外のステージで「おさらい」の札の付いた問題が出る（町テストに出す日が来た問題を用意して確かめ、確認後に元へ戻す）
- 相棒の復習が10問まで出る
- パスポートの「覚えた問題」
- 確認のあと、開発用のデータが確認前と同じであることを確かめる

## 7. やらないこと

- その回の中で、まちがえた問題を最後にもう一度出して記録する（今の「まちがえた問題だけもう一度」の練習のまま）
- 覚えた問題を見返す一覧・覚え具合の細かい表示（「覚えた問題 N」の数だけ出す）
- 問題ごとの難しさで間を変えること
- 学ぶタブの地図（別の設計で扱う）
