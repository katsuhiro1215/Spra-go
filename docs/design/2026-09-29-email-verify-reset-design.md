# メール確認・パスワード再設定のページ — 設計書

- 作成日: 2026-09-29
- ステータス: Owner合意済み（メール確認の求め方〔お知らせ＋コインを買う前だけ必須〕、確認のリンクの受け方、画面ごとの中身、開発用のメールの道具を対話で確認）
- 前提: ログイン・登録（`app/login`・`app/register`）、コインの購入（Stripe。`SPEC.md` 4-6）、スプルのアイコン（手紙のスプル `SPRU_ICONS.letter`・鍵のスプル `SPRU_ICONS.key`。`docs/design/2026-09-29-spru-icons-design.md`）。どれも実装済み
- 対応するタスク: `TASKS.md` 開発部門「メール確認・パスワード再設定のページを作る」（公開前必須）

## 1. 背景と目的

サーバーには、パスワード再設定とメール確認の仕組み（Laravel Breeze の `routes/auth.php`）がある。ただ、次の状態のまま公開できない。

- パスワード再設定の画面（`/forgot-password`・`/password-reset/[token]`）は英語の見出しだけで、ログイン画面からもつながっていない。パスワードを忘れた親が、自分で戻れない
- 利用者のアカウント（`User`）はメール確認を求めない設定で、確認メールが送られていない。打ち間違えたアドレスで登録すると、パスワード再設定のメールもコインの購入の連絡も届かない
- 確認のリンクは、同じブラウザでログインしていないと使えない。確認したあとの戻り先も、今はない古い画面（`/dashboard`）になっている
- メールの差出人の名前が「Laravel」のまま。開発ではメールを送らず記録に書くだけ（`MAIL_MAILER=log`）で、中身を確かめにくい

**うまくいった目安**

1. ログイン画面から、パスワードを忘れたときの画面へ進み、届いたメールのリンクから新しいパスワードを決めて、ログインできる
2. 登録すると確認メールが届き、スマホのメールアプリなど、ログインしていないブラウザで開いても確認できる
3. 確認していないあいだは、親が見る画面にお知らせが出て、コインは買えない。子どもが遊ぶ画面は止まらない
4. 開発では、送ったメールをブラウザ（Mailpit）で開いて、リンクを押して確かめられる

## 2. 決定事項（Owner確認済み）

| 項目 | 決定 |
|---|---|
| メール確認の求め方 | 登録すると確認メールを送る。遊ぶのは止めず、確認していないあいだはお知らせを出す。コインを買うときだけ確認を必須にする |
| お知らせを出す所 | プロフィール選びの画面（親が見る所）と、ショップのコイン購入の欄。町・学ぶなど子どもが遊ぶ画面には出さない |
| 確認のリンクの受け方 | ログインしていなくても確かめられる形。リンクの期限付きの署名を確かめて確認済みにし、画面の結果のページへ移す |
| リンクの有効期限 | 確認のリンクは24時間（親が後で開いても間に合うように）。パスワード再設定のリンクは今のまま60分 |
| パスワードを忘れたときの受付 | 登録の有無に関係なく同じ返事にする（登録されているアドレスかを知られないため） |
| メールの文面 | Laravel の日本語の文面（`lang/ja.json` に翻訳がある）を使う。差出人の名前は「Spra Go」 |
| 開発用のメール | Mailpit（送ったメールをブラウザで見られる無料の道具）を開発用の構成に足す |
| 本番のメールの送り先 | 本番の構成を決めるとき（`TASKS.md`「本番デプロイの大枠設計」）に選ぶ。今回は決めない |

## 3. 画面

どの画面も、今のログイン・登録の画面と同じ形（空の背景・クリーム色のカード・スプルの絵）にする。文は親に向けた丁寧すぎない言い方にし、漢字にはふりがな（`AutoFurigana`）を付ける。

### 3-1. ログイン画面（`/login`）

- パスワードの欄の下に「パスワードを忘れたら」のリンクを足す（`/forgot-password` へ）
- 新しいパスワードを決めたあとに来たとき（`/login?reset=1`）は、カードの上に「新しいパスワードでログインしてね」と出す

### 3-2. パスワードを忘れたとき（`/forgot-password`）

- 手紙のスプル（`SPRU_ICONS.letter`）、見出し「パスワードを忘れたとき」、説明「登録したメールアドレスを入れてね。パスワードを決め直すためのメールを送ります」、メールアドレスの欄、「メールを送る」ボタン、「ログインにもどる」リンク
- 送ったあとは、欄とボタンの代わりに「メールを送りました。届いたメールのリンクから、新しいパスワードを決めてね。メールが届かないときは、迷惑メールのフォルダも見てね」と出す。登録のないアドレスでも同じ表示
- メールアドレスの形がおかしいときだけ、欄の下に直し方を出す

### 3-3. 新しいパスワード（`/password-reset/[token]?email=…`）

- 鍵のスプル（`SPRU_ICONS.key`）、見出し「新しいパスワード」、メールアドレス（リンクから入れておき、直せる）、新しいパスワード、もう一度入れる欄、「8文字以上」の添え書き、「パスワードを決める」ボタン
- うまくいったら `/login?reset=1` へ移る
- リンクが古い・正しくないとき（サーバーが token のまちがいを返したとき）は「リンクが古いか、正しくありません。もう一度メールを送ってね」と、`/forgot-password` へのリンクを出す
- パスワードが短い・2つが違うときは、欄の下に出す

### 3-4. メール確認の結果（`/verify-email?status=…`）

確認のリンクを押すと、サーバーが確かめたあと、この画面に移る。`status` で出し分ける。

| status | 出すもの |
|---|---|
| `verified` | 手紙のスプル、「メールアドレスを確かめました」「これでコインも買えるようになりました」。ログインしていれば「つづける」（`/profiles` へ）、していなければ「ログイン」 |
| `expired` | 「リンクの期限が切れています」。ログインしていれば「もう一度メールを送る」ボタン、していなければ「ログインすると、もう一度送れます」と「ログイン」 |
| `invalid` とそれ以外 | 「リンクが正しくありません」。ボタンは `expired` と同じ |

### 3-5. 確認していないときのお知らせ

- プロフィール選びの画面（`/profiles`）のカードの上と、ショップのコイン購入の欄の上に出す
- 文: 「メールアドレスを確かめてね」「登録したメールアドレスに届いたメールのリンクを押すと、コインを買えるようになります」と、「メールをもう一度送る」ボタン
- ボタンを押したら「メールを送りました」に変える。短い間に何度も押したとき（サーバーが断ったとき）は「少し時間をおいてから、もう一度押してね」
- 確認済みかどうかは、今もログインのたびに読んでいる `GET /api/user` の `email_verified_at` で決める

### 3-6. コインの購入（ショップ）

- 確認していないあいだは、コインのパックの「購入する」ボタンを押せない（薄くする）。押せない理由は3-5のお知らせで伝える
- サーバーが断った場合（別の画面で確認が外れていたときなど）は、サーバーの文をそのまま出す

## 4. サーバー

### 4-1. 利用者のアカウントを「メール確認あり」にする

- `App\Models\User` を `MustVerifyEmail` にする。登録（`RegisteredUserController`）はもう `Registered` のイベントを出しているので、Laravel の決まりで確認メールが自動で送られる
- 画面全体を止める仕組み（`verified` のミドルウェア）は、利用者の画面には付けない。止めるのはコインの購入だけ（4-3）
- 運営側（Owner・管理者）の確認とパスワード再設定の流れは変えない

### 4-2. 確認のリンク（`GET /verify-email/{id}/{hash}`）

- ログイン（`auth`）を求めない形にする。期限付きの署名（`signed`）と、`hash` がそのアカウントのメールアドレスの `sha1` と一致するかで確かめる。回数の制限（`throttle:6,1`）は今のまま
- 結果に応じて、画面の `/verify-email?status=…` へ移す
  - 署名が正しくない・期限が切れている → `expired`
  - アカウントがない・`hash` が合わない → `invalid`
  - もう確認済み → `verified`（もう一度確認済みにはしない）
  - 確認できた → 確認済みにして `Verified` のイベントを出し、`verified`
- 署名の期限切れで Laravel が403の画面を出さないよう、署名はコントローラーの中で確かめる
- 有効期限は `config/auth.php` に `'verification' => ['expire' => 1440]` を足して24時間にする（今のリンクの作り方〔`AppServiceProvider`〕は、この設定を読む）

### 4-3. コインの購入の前に確かめる（`POST /api/coin-purchases/checkout`）

- 確認していないアカウントは、Stripe の手続きを始める前に断る: 403、`{ "message": "メールアドレスを確かめると、コインを買えるようになります。", "code": "email_unverified" }`
- 確認済みなら今のまま

### 4-4. パスワードを忘れたとき（`POST /forgot-password`）

- メールアドレスの形のチェックは今のまま
- そのあとは、アカウントがない・短い間に何度も頼んだ、のどれでも、送れたときと同じ返事（200、`{ "status": "…" }`）にする。送るかどうかは Laravel の仕組み（`Password::sendResetLink`）に任せる
- 新しいパスワードにする処理（`POST /reset-password`）は今のまま（token のまちがいは、今どおり `email` の欄のエラーとして返る）

### 4-5. メールの差出人と文面

- 差出人の名前とメールの上の名前は、アプリの名前（`APP_NAME`）から作られる。開発の `.env` と `.env.example` の `APP_NAME` を「Spra Go」にする
  - ログインのクッキーとキャッシュの名前もアプリの名前から作られるので、開発ではログインがいったん切れる（ログインし直せばよい）。本番は公開前なので影響はない
- 結びの「よろしくお願いします,」（`lang/ja.json` の `Regards,`）は、読点を「よろしくお願いします。」に直す
- 差出人のアドレス（`MAIL_FROM_ADDRESS`）は、本番のメールの送り先を決めるときに決める

## 5. 開発用のメール（Mailpit）

- Sail の Mailpit を足す（`compose.yaml` にサービスを足す）。送ったメールは `http://localhost:8025` で見られる
- 開発の `.env` のメールの項目を Mailpit に向ける（`MAIL_MAILER=smtp`・`MAIL_HOST=mailpit`・`MAIL_PORT=1025`）。`.env` は秘密の情報が入ったファイルなので、書き換える前にOwnerに確認する
- `.env.example` も同じ値にそろえる（秘密の情報は入っていない）
- テスト（Pest）はメールを実際には送らない（今どおり）

## 6. テスト

### 6-1. サーバー（Pest）

- 登録すると、確認メール（`VerifyEmail` の通知）がそのアカウントに送られる
- 確認のリンク
  - ログインしていなくても確認でき、`/verify-email?status=verified` へ移る
  - 署名が正しくない・期限が切れたリンクは `expired` へ移り、確認済みにならない
  - `hash` が合わないリンクは `invalid` へ移る
  - もう確認済みのアカウントは `verified` へ移る
  - リンクは24時間有効（23時間後は確認でき、25時間後は `expired`）
- 確認していないアカウントはコインの購入を始められない（403・`email_unverified`）
- パスワードを忘れたとき、登録のないアドレスでも、登録のあるアドレスと同じ返事になり、メールは送られない

### 6-2. 画面（Vitest）

計算だけの部品にして確かめる。

- 確認の結果の出し分け（`verified`・`expired`・`invalid`・それ以外 → 見出し・文・もう一度送れるか）
- 確認済みかどうか（`email_verified_at` があるか）
- 新しいパスワードのエラーの出し分け（token のまちがい → 「リンクが古いか…」、パスワードのまちがい → 欄の下）

### 6-3. ブラウザでの確認

- 新しいアカウントで登録 → プロフィール選びにお知らせ → Mailpit で確認メールを開いてリンクを押す → 結果の画面 → お知らせが消える
- ショップで、確認前はコインの購入ボタンが押せず、確認後は押せる（Stripe の画面へは進まない）
- ログイン画面 → パスワードを忘れたら → メールを送る → Mailpit でメールを開く → 新しいパスワード → ログイン
- 登録のないアドレスでも「メールを送りました」と出る
- 幅320・390・1280pxで画面が崩れない
- 確かめたあと、試しに作ったアカウントを消し、町テストのデータが確認前と同じか確かめる

## 7. やらないこと

- 本番のメールの送り先（Amazon SES など）の選択と設定、差出人のアドレスの決定（本番デプロイの設計で行う）
- メールの見た目（Spra Go のロゴや色）の作り込み。Laravel の初期のメールの形のまま
- メールアドレスの変更の画面（今は変える画面がない）
- 使っていない古い画面（`/dashboard`）の片付け
- 決済前の追加認証（パスワードの再入力など。`TASKS.md` の別の公開前必須の仕事）
